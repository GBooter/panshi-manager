## 0. 三十秒上手

### 0.1 项目一句话

deepin 25 磐石系统（OSTree 只读根 + 可写层）的图形化管理工具。
七个页面 + 一个后台监控进程；本仓库是 PyQt6 原版的 **C++/Qt6/DTK6 原生重写版**。

### 0.2 环境与构建

**正常开发机（deepin 25）**：

```bash
sudo apt install -y cmake g++ make pkg-config \
    qt6-base-dev qt6-svg-dev qt6-tools-dev-tools \
    libdtk6core-dev libdtk6gui-dev libdtk6widget-dev

cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

**本仓库的实际开发环境是只读容器**（`/etc`、`/usr` 不可写，apt 无 dpkg 锁，sudo 失效），
工具链是项目内自建 sysroot，**每次开新终端都要先 source**：

```bash
source .toolchain/env.sh          # PATH / LD_LIBRARY_PATH / CMAKE_PREFIX_PATH / TMPDIR
cmake -B build2 -DCMAKE_BUILD_TYPE=Release
cmake --build build2 -j"$(nproc)"
```

> ⚠️ **两个构建目录都是活的**：`build/` 与 `build2/` 同源（2026-10-04 已在两边都补做过 cmake 配置）。
> 用户习惯跑 `./build/panshi-manager`。
> **若 `build/` 里没有 `CMakeCache.txt`，那它是陈旧产物，跑的不是最新代码** —— 改完代码两边都要编。
> 判断依据：对比二进制时间戳/大小（`build/` 曾是 3.4MB / `build2/` 是 30MB，差一个数量级）。
> 详见 [§7.10](#f1-增量构建与陈旧产物会掩盖缺陷)。

### 0.3 跑起来 / 自检

```bash
# 直接开发运行（不安装）
QT_QPA_PLATFORMTHEME=deepin ./build2/panshi-manager

# 后台监控跑一轮（不需要 root 也能跑，只是数据不完整）
./build2/panshi-manager --monitor

# 造测试数据（默认干跑，--go 才写）
python3 make-testdata.py            # 干跑
python3 make-testdata.py --go spike  # 造「异常增长 + 告警横幅」场景

# C 类实机验证（默认干跑，--go 才执行）
./verify-runtime.sh                # 干跑：打印将要做什么
./verify-runtime.sh --go            # 实跑
./verify-runtime.sh --go colors     # 只跑配色断言段
```

### 0.4 一次改动的标准流程

```
1. 读本文相关章节（第 3 章有你要做的任务的模板）
2. 改代码（当轮就编译，别攒着）
3. 跑验收计数（第 6.5 节）
4. 跑探针（第 6.2 节，15 个探针 target）
5. 改到的东西如果是"看得见/听得出"的 → 补一条断言
6. 补 i18n（lupdate + 译文）
7. 更新本文 / 开发文档.md 里受影响的描述
8. 追加 .workbuddy/memory/YYYY-MM-DD.md 日志（写清"为什么"，不是"改了什么"）
```

### 1.2 依赖方向（谁能 include 谁）

**核心约束：组件层不认识页面，页面不认识主窗口。** 反向依赖只能通过基类注册点或信号回调。

```
                  ┌──────────────────────┐
                  │  main.cpp            │  DApplication / D-Bus / 主题信号
                  │  mainwindow.{h,cpp}  │  PageId / 侧栏接线 / 到达动作
                  └──────────┬───────────┘
                             │ 只用基类指针 BasePage* / Q_INVOKABLE
                  ┌──────────▼───────────┐
                  │  pages/*             │  页面：可用组件层全部能力
                  └──────┬────────┬──────┘
                         │        │
        ┌────────────────▼──┐  ┌──▼─────────────────┐
        │ ui/components.*   │  │ backend.{h,cpp}    │  只依赖 Qt，不依赖任何项目头
        │ ui/confirmdialog  │  └──────────┬─────────┘
        │ ui/tokens.h       │             │
        │ pages/common.h    │  ┌──────────▼─────────┐
        └────────────────────┘  │ disk/*             │  只依赖 QtCore/Concurrent
                                └────────────────────┘
```

**允许**：
- `pages/*` → `ui/components.h`、`pages/common.h`、`backend.h`、`disk/*`
- `ui/*` → `ui/tokens.h` + DTK + Qt
- `disk/*`、`backend.*` → 只依赖 Qt（**这两个目录必须保持零 UI 依赖**，因为 `--monitor` 无界面进程会链接它们）
- 页面间跳转 → `gotoPage()` + `Q_INVOKABLE` 动作契约，**不 include 对方头文件**

**禁止**：
- `ui/components.h` 反向 `#include "mainwindow.h"` 或任何页面头
- `backend.*` / `disk/*` 里出现 `#include <DWidget>` 之类
- 在 `namespace PanshiUi {}` 内部写前置声明（会声明出不存在的嵌套类型，见 [教训 D6](#d6-q_object-与命名空间前置声明)）

## 2. 架构骨架

### 2.1 分层图

```
┌──────────────────────────────────────────────────────────────────┐
│ UI 层  ui/* + pages/* + widgets/*                                 │
│   颜色取自 DPalette · 度量取自 tokens.h · QSS 只管布局            │
│   BasePage::runAsync 后台执行 + 三档加载（L1骨架/L2局部/L3细条）   │
└───────────────┬──────────────────────────────┬───────────────────┘
                │ 同步调用（QtConcurrent 工作线程）│ 异步信号
┌───────────────▼──────────────┐  ┌────────────▼───────────────────┐
│ backend.{h,cpp}              │  │ disk/*（GUI 侧实例）           │
│ 磐石命令封装                 │  │  Store / Scanner / MonitorConfig│
│ ostree / ctl / df / du /     │  └────────────┬───────────────────┘
│ systemctl / gio / D-Bus      │               │
└───────────────┬──────────────┘               ▼
┌───────────────▼──────────────────────────────────────────────────┐
│ 后台进程：panshi-manager --monitor                                │
│   systemd user timer 每 15 分钟拉起，跑一轮就退出                  │
│   与 GUI 共享 src/disk 代码 + ~/.local/share/panshi-manager 数据   │
└──────────────────────────────────────────────────────────────────┘
```

**GUI 与监控进程共享 `src/disk/*`** —— 这是"一份逻辑两处用"的关键设计：
GUI 直接 `DiskHistoryStore` 读数据，监控进程写数据，两边看到同一批文件。
→ **因此 `disk/*` 里绝对不能引入 UI 依赖**（`--monitor` 走 `QCoreApplication`，无 GUI）。

### 2.2 线程模型

| 执行位置 | 承载什么 | 注意 |
|---|---|---|
| 主线程 | 全部 UI；`QProcess` 事件循环 | — |
| QtConcurrent 工作线程 | `BasePage::runAsync(fn, onDone)` 里的 `fn`（= backend 同步调用）；`DiskHistoryStore::requestRange` 的逐日读文件 | 回调统一回主线程 |
| 独立进程 | `--monitor`（oneshot，每 15 分钟） | 写文件靠原子写（临时文件 + rename） |
| 独立进程 | 手动扫描时的 `du`（`DiskScanner` 用 `QProcess` 流式解析，带 `nice -n 19` + `ionice -c3`） | 不阻塞 UI，可取消 |

**`runAsync` 的时序契约（改这个模板时必须保留）**：

```cpp
connect(watcher, &QFutureWatcher<QVariant>::finished, this, [this, watcher, onDone] {
    const QVariant res = watcher->result();
    watcher->deleteLater();
    hideLoading();
    onDone(res);   // ← 先 onDone
    endTask();    // ← 再 endTask
});
```

> **为什么必须这个顺序**：`onDone` 里常常接着发起第二段任务（总览页 = 快速状态 → 慢速统计）。
> 先 `onDone` 会让 `beginTask` 把计数抬到 2，再 `endTask` 落回 1 —— 计数不归零，
> 就不会误发 `idleReached()` 让「到达后动作」在半程就执行。
> 顺序写反的症状：跨页跳转的动作在数据还没齐时就去执行。

### 2.3 五个关键机制

#### (1) 注册点范式（本项目最核心的解耦手段）

组件层/base class 不知道具体页面长什么样，于是**由页面在构造时把「我有什么」注册上去**：

| 注册点 | 页面调什么 | 基类做什么 | 不注册的后果 |
|---|---|---|---|
| 反馈 Banner | `setFeedbackBanner(banner)` | `showFeedback()` 有地方显示 | **反馈静默消失**（无编译告警） |
| 响应式卡片行 | `registerResponsiveCardRow(row, scroll, pad)` | 监听 viewport resize + showEvent，喂 `setAvailableWidth()` | 窄窗下横向溢出且被静默裁掉 |
| 设置搜索 | `registerSearchTarget(key, row, scroll)` + `searchableSettings()` | 索引能定位并高亮该行 | 搜索能搜到但点过去不定位 |
| 可用动作 | `Q_INVOKABLE void requestXxx()` | 供 `gotoPage(id, action)` 远程调用 | 跨页快速操作无从下手 |
| 忙碌状态 | 复合页覆写 `isBusy()` 聚合子页 | 到达动作等真正空闲 | 动作在子页数据未就绪时提前执行 |

> ⚠️ **「注册类方法漏调 = 静默失效」**。历史上 6 个页面里只有 2 个调过 `setFeedbackBanner()`，
> 症状是"那 4 页的操作成功/失败没有任何提示"，日志里什么都看不到。
> **排查"反馈不出现 / 高亮不触发 / 窄窗布局错乱"，第一步永远是查有没有调注册。**
> 详见 [§7.2](#b1-注册类方法漏调)。

#### (2) 强类型页面标识

```cpp
enum class PageId { Overview, DiskUsage, BackupVersion, Protection, Policy, Update, About };
```

历史用 `gotoPage(int)` + `m_pages.at(n)`，页面顺序一变就跳错页。
现在下标与页面解耦，`PageId` 是唯一入口，编译期排除错误。

> `m_pages` 是 `QMap<PageId, BasePage*>`，按 key 升序迭代，而枚举顺序 = 期望导航顺序，
> 所以 `insert` 顺序与 `QStackedWidget` 下标天然一致。**新增页面时枚举值要插在正确的位置。**

#### (3) 跨页「到达后动作」

```
总览「立即创建备份」
   → gotoPage(BackupVersion, action)
       → switchTo()：切栈 + 侧栏选中 + refresh()（异步）
       → scheduleArrivalAction()：挂到目标页 idleReached()，4s 超时兜底
           → refresh 完成 → idleReached → action() → 打开创建对话框
```

四个必须保留的细节：
1. **后到覆盖先到**（用户最后一次点击最符合意图），覆盖时 `disconnect` 旧宿主
2. **切页作废**（`switchTo` 开头 `flushArrivalAction(false)`）——用户改主意点侧栏后旧动作再弹出就是误操作
3. **`isBusy()` 为 false 时立即执行**（refresh 是同步的，别等一个永不到来的信号）
4. **先清状态再执行**（动作内部可能再次 `gotoPage`）

#### (4) 语义色收敛

```cpp
enum class Semantic { Muted, Normal, Accent, Success, Warning, Danger };
QColor semanticColor(Semantic);   // 唯一查询入口
void  applySemantic(DLabel *, Semantic);
QColor softFill(Semantic, int alpha = Alpha::SoftFill);
```

- **Danger 与 Warning 同色**（都是 `DPalette::TextWarning`），两级语义靠**图标 + 文案 + 控件类型**区分 —— 刻意设计，满足 WCAG 1.4.1
- `semanticColor()` 与 `applySemantic()` **必须同步改**，漏一处 = 色块红、小字黑
- 改颜色映射前先看 [§7.1](#组-a文档--命名--既成事实必须实测)

#### (5) 三档加载分级

| 档 | 组件 | 用在哪 |
|---|---|---|
| L1 | `PanshiSkeleton` 骨架屏 | 首次进入且无任何数据（与最终结构同形） |
| L2 | `PanshiLocalLoading` 局部 spinner | 目标容器内部，其余内容保持可读 |
| L3 | `PanshiFlatProgress` 顶部细进度条 | 长任务（扫描/还原/升级） |

**不再有全页遮罩**。页面已有 L2 时调 `setMaskLoadingEnabled(false)`。
`runAsyncQuiet` 用于"切标签页预读"——紧跟用户点击后再弹灰屏会闪两次。

### 2.4 一次 refresh 的完整链路

以磁盘页为例，看数据怎么从系统命令走到像素：

```
DiskUsagePage::refresh()
  → runAsync([&]{ return DiskHistoryStore::loadIndex(); }, onDone)   [工作线程]
      → 读 ~/.local/share/panshi-manager/disk-history/index.json
      → 索引缺失/损坏 → rebuildIndex() 扫全目录重建
  → onDone(回主线程)
      → requestRange(begin, end)  [工作线程逐日读]
          → rangeProgress / rangeLoaded(带 requestId，支持取消与防抖)
      → onRangeLoaded
          → setRecords(records) → UsageChart::setRecords()
              → 跨度 ≤180 天：柱状图；>180 天：自动切折线/面积
              → 逐柱 reveal 动画（尊重「减少动态效果」）
      → rebuildSpikeSet / updateTable / updateOverview
          → updateOverview 用 usageSemanticForPct() 决定数值语义色
      → endTask() → idleReached() → 到达动作（如有）
```

QList<BootEntry> getBootEntries()
{
    QList<BootEntry> out;

    const CommandResult r = runProcess(QStringLiteral("systemctl"),
                                       QStringList() << "list-unit-files" << "--type=service",

    if (!r.ok) return out;      // ⚠️ 解析类函数失败返回空容器，不抛异常、不弹窗
    for (const QString &line : r.stdoutText.split('\n', Qt::SkipEmptyParts)) {
        BootEntry e;
        // ... 解析
        out.append(e);
    }
    return out;
}

CommandResult setBootEnabled(const QString &id, bool on)
{

### 3.9 新增一个探针（自动化验证）

**判断该不该自动化**：这个缺陷能不能被"看见/听得出"？
能 → 就该有断言，肉眼验证是最贵的。

```cmake
# CMakeLists.txt
add_executable(panshi-myprobe
    tools/probe_myfeature.cpp     # 独立探针放 tools/
    src/ui/components.cpp         # 需要复用组件层时，把它也列进来
)
target_include_directories(panshi-myprobe PRIVATE src)
target_link_libraries(panshi-myprobe PRIVATE
    Qt6::Core Qt6::Gui Qt6::Widgets Qt6::Svg
    Dtk6::Core Dtk6::Gui Dtk6::Widget
)
# 探针一律「不安装」——没有 install(TARGETS ...)
```

**探针骨架**（照抄本项目 15 个探针的共同结构）：

```cpp
// 探针共用的断言辅助（每个探针里各有一份，签名统一）
static int g_fail = 0;
static void check(bool ok, const QString &what)
{
    QTextStream o(stdout);
    o << (ok ? "  ok   " : "  FAIL ") << what << "\n";
    if (!ok) ++g_fail;
}

int main(int argc, char *argv[])
{
    // ⚠️ 1. qputenv 必须在 QApplication/DApplication 构造**之前**：
    //    平台插件在构造时选定，之后再设无效。
    //    offscreen 可避免抢焦点、也不需要 DISPLAY。
    qputenv("QT_QPA_PLATFORM", "offscreen");
    // 涉及用户数据时还要隔离（historyDir() 走 GenericDataLocation）：
    // qputenv("XDG_DATA_HOME", "/tmp/probe-xxx");

    DApplication app(argc, argv);
    app.setApplicationName(QStringLiteral("panshi-manager"));

    // 可选：QCommandLineParser 支持 --pct / --theme，便于脚本单点复测
    // （照抄 colorprobe.cpp 的写法）

    // 需要暗色时：进程内强制，不依赖系统 gsettings（本机系统级暗色不可达）
    DGuiApplicationHelper::instance()->setPaletteType(DarkType);

    // ⚠️ 2. 断言前先校验前置条件（否则 nullptr 崩溃掩盖后续全部断言）
    auto *w = makeThing();
    check(w != nullptr, QStringLiteral("前置：对象创建成功"));
    if (!w) {
        QTextStream(stdout) << "前置失败，跳过其余断言\n";
        std::exit(1);
    }

    check(w->value() == 42, QStringLiteral("契约：value() 返回 42"));

    // ⚠️ 3. 退出必须用 std::exit(1)，不能用 QCoreApplication::exit(1)
    QTextStream o(stdout);
    if (g_fail == 0) o << "PASS: 全部断言成立\n";
    else             o << "FAIL: " << g_fail << " 条断言未通过\n";
    std::exit(g_fail == 0 ? 0 : 1);
}
```

**三条硬约束**：

| 约束 | 原因 |
|---|---|
| ⚠️ **必须 `std::exit(1)`** | `QCoreApplication::exit(1)` 在纯同步 `main()`（无事件循环）里**只设事件循环返回值**，会被后面的 `return 0` 覆盖 → **缺陷存在时照样报 PASS** |
| ⚠️ **断言渲染结果，不断言"我以为的值"** | 本项目踩过 `TextLively` 名为警示色、实测中性黑的坑。只断言"我调了 `setForegroundRole`"抓不到那种失效 → **必须采样像素** |
| ⚠️ **判据与被测代码同源** | 页面与探针共用 `usageSemanticForPct()` / `kUsageWarnPct`，改阈值两边同步，杜绝"页面已改、断言按旧阈值"的假绿 |

**修完缺陷必须双向验证**：

```
临时回退修复 → 探针必须 FAIL   ← 证明探针真的能抓到这个缺陷
恢复修复     → 探针必须 PASS
```

再加一条**反向对照**防"修过头"：例 —— 修"空索引不写盘"要配一条"有数据时仍必须写盘"。

**纯 shell 类探针**（需要 moc 或自建编译链时）照 `tools/verify-history-flicker.sh` 抄：
`source .toolchain/env.sh` → 跑 moc → g++ 手编 → 隔离 `XDG_DATA_HOME` 跑 → 按退出码报 RESULT。


### 3.10 新增一个跨页跳转动作

例如总览页加「立即检查更新」→ 跳更新页并自动开始检查。

**Step 1 — 目标页暴露 `Q_INVOKABLE` 动作契约**

```cpp
// updatepage.h
public:
    /** 跨页跳转契约：被 MainWindow 经元对象调用，外部无需持有本页头文件 */
    Q_INVOKABLE void requestCheckUpdate();
```

```cpp
// updatepage.cpp
void UpdatePage::requestCheckUpdate()
{
    if (m_running) return;      // ⚠️ 防重入守卫必须有
    onCheckClicked();            // 内部复用正常点击路径，不要复制逻辑
}
```

**Step 2 — 源页用 `QMetaObject::invokeMethod` 触发**

```cpp
// overviewpage.cpp 的真实写法 —— 总览页**不持有**目标页头文件：
m_win->gotoPage(PageId::BackupVersion, [this] {
    QMetaObject::invokeMethod(m_win->page(PageId::BackupVersion),
                              "requestCreateSnapshot", Qt::DirectConnection);
});
// 传 Qt::DirectConnection：动作要在 idleReached 里同步跑完
```

三处调用点（`overviewpage.cpp:128/135/144`）都用这个模式 ——
`requestCreateSnapshot` / `requestCheckUpdate` / `highlightEnableProtect`。

**Step 3 — 复合页要聚合忙碌状态** ⚠️

如果目标页是 tab 复合页（如 `VersionManagementPage`），**必须覆写 `isBusy()`**：

```cpp
bool VersionManagementPage::isBusy() const
{
    // 本页自身计数恒为 0（refresh 转发给子页），必须聚合子页，
    // 否则「到达后动作」会在子页数据未就绪时提前执行
    return m_snapPage->isBusy() || m_deployPage->isBusy();
}
```

**Step 4 — 复合页内部继续用 invokeMethod 转交子页**

```cpp
void VersionManagementPage::requestCreateSnapshot()
{
    showSubPage(0);                                  // ⚠️ 先切子页
    QMetaObject::invokeMethod(m_snapPage, "onCreate", Qt::DirectConnection);
}
```

**Step 5 — 子页切换必须在 `switchTo()` 之前**

`gotoPage(id, sub, afterArrive)` 的实现里，子页切换要先做完，
否则 `refresh()` 刷到的是旧子页，随后到达动作作用在一个尚未加载的子页上。

## 4. UI 编码红线

> 这些不是"建议"，是本项目**验收时用 grep 硬断言**的规则。

### 4.1 颜色：职责归 `DPalette`，QSS 只管布局

```cpp
// ✅ 正确：语义入口
PanshiUi::applySemantic(label, PanshiUi::Semantic::Warning);
QColor c = PanshiUi::semanticColor(PanshiUi::Semantic::Danger);
QColor bg = PanshiUi::softFill(PanshiUi::Semantic::Accent);

// ✅ 自绘控件：paintEvent 内实时取
void MyWidget::paintEvent(QPaintEvent *) {
    QPainter p(this);
    p.setBrush(PanshiUi::baseColor());
}

// ❌ 禁止：任何 hex 色值
setStyleSheet("color: #ff5837");
QColor c = QColor("#ff5837");

// ❌ 禁止：QSS 属性选择器染色
setStyleSheet("#panshiStatValue[stat=danger] { color: red; }");

// ❌ 禁止：构造时缓存颜色
QColor m_c = DPalette().color(DPalette::TextWarning);   // 切主题会停在旧色
```

**语义映射表**（改映射须**同步 `semanticColor()` 与 `applySemantic()`**，漏一处 = 色块红、小字黑）：

| Semantic | DPalette 角色 | 用途 |
|---|---|---|
| `Muted` | `TextTips` | 说明 / 次要文字 |
| `Normal` | `TextTitle` | 正文 / 标签 |
| `Accent` | `Highlight` | 强调值（跟随用户主题色） |
| `Success` | `Highlight` | 成功 / 正常 |
| `Warning` | `TextWarning` | 警告 |
| `Danger` | `TextWarning` | 危险（⚠️ 与 Warning 同色，**刻意**） |

> **Danger 曾映射到 `TextLively`，实测其默认主题取值是中性黑** —— 危险语义完全失效。
> DTK 里 `TextLively` 的语义是「活跃式文本（不受活跃色影响）」，本就不是危险色。
> 代价是两级语义同色，靠**图标 + 文案 + 控件类型**区分（WCAG 1.4.1）。
> 详见 [§7.1](#组-a文档--命名--既成事实必须实测)。

### 4.2 字号：走 `DFontSizeManager`，禁 QSS `font-size`

```cpp
DFontSizeManager::instance()->bind(label, DFontSizeManager::T5);
PanshiUi::makeLabel(text, PanshiUi::TextLevel::Body, PanshiUi::Semantic::Normal);
```

`TextLevel` → DFontSizeManager 映射：`PageTitle`=T2 / `Value`=T2（刻意与页面标题同级）/
`SectionTitle`=T5 / `Body`=T5 / `ValueSmall`=T4 / `Desc`=T6 / `Aux`=T7 / `Mono`=T8（命令/ID）。

### 4.3 度量：走 `tokens.h`，禁硬编码

| namespace | 内容 |
|---|---|
| `Space` | XS 4 / S 8 / M 12 / L 16 / XL 24 / XXL 32 |
| `Radius` | Element 4 / Frame 8（对齐 DTK `PM_FrameRadius`） |
| `Size` | Icon 16/20/24/32、RowControlMinWidth 200、StateCardMinWidth 168、… |
| `Motion` | Micro 150 / State 250 / PulsePeriod 1200 / HighlightHold 1200 / HighlightFade 320 |
| `Alpha` | SoftFill 38（≈15%）/ BannerFill 51（≈20%）/ Outline 51 |

`tokens.h` **不含任何颜色** —— 这是它与 `style.h` 的职责分界。

### 4.4 反馈：页内 Banner，禁止模态

```cpp
// ✅ 成功：自动消失，可关
showFeedback(PanshiUi::Semantic::Success, tr("已创建备份「%1」").arg(name), /*autoHide=*/true);

// ✅ 失败：常驻可关 + 原始输出收进「详情」折叠块
showFeedbackWithDetails(PanshiUi::Semantic::Danger,
                       tr("创建失败，请检查是否已在 sudoers 组中"),
                       tr("完整输出"), result.errorMessage);
```

- **成功类操作 0 次模态弹窗**（模态框要求用户再点一次确定，且盖住刚改动的界面）
- 原始输出（ostree/deepin-immutable-ctl 的多行 stderr）**不要拼进正文** ——
  正文只留一行可行动说明，原始输出收进默认收起的详情
- `autoDismiss()` 重复调用会**重置**倒计时而不是叠加（否则旧定时器会在新内容刚显示时隐藏整条）

### 4.5 确认：全应用唯一实现

```cpp
PanshiUi::ConfirmRequest req;
req.title        = tr("删除备份");           // 必须是动作，不是「确认」
req.consequences = {tr("备份数据将被永久删除"), tr("无法恢复")};
req.confirmText  = tr("删除");                 // 禁止「确定」
req.level        = PanshiUi::DialogLevel::Danger;
if (!PanshiUi::askConfirm(this, req)) return;
```

`Ui::confirmDialog()` 只是既有调用点的薄封装。**不存在第二个确认实现。**

### 4.6 布局与挤压：显式最小宽度是唯一可靠防线

```cpp
// 表格列
table->setColumnWidth(i, w);
table->horizontalHeaderItem(i)->setText(...);

// 交互控件行
m_row->addControl(spin);              // 默认下限 200

// 纯文本值行
m_row->addControl(valueLabel, 0);     // ⚠️ 显式传 0，允许优雅退化
```

三条反直觉规则：

1. **外层 `QScrollArea` 若 `ScrollBarAlwaysOff`，内层溢出被静默裁掉**（不可达、看不见、无日志）
2. **`QStackedWidget` 隐藏页不跟随 resize** → 响应式必须走 `BasePage::registerResponsiveCardRow()`；
   「读自身宽度」会自锁（卡片行宽度受列数影响，须用 viewport 宽度作输入）
3. **`ElidedLabel` 横向策略不能是 `Ignored`** ——
   `Ignored` 在布局分配中 sizeHint 记 0，与带 stretch 的兄弟项同处一行时，
   富余宽度全被文本列吸走，本控件被分到 0 宽、什么都不画（总览页「系统信息」四行值整体消失）
   → 改回 `Preferred` + `minimumSizeHint()` 返回 24。

### 4.7 图标：`DIconTheme` + 回落，禁内嵌 SVG 字符串

```cpp
// ✅ 五级回落链见 §3.7
QIcon ic = Ui::themedIcon(name, QStyle::SP_DriveHDIcon);
```

> ⚠️ **图标是「快照」**：`QIcon::pixmap()` 出来的图不会随主题更新。
> 用 `Ui::iconBadge()`（已挂 `applicationPaletteChanged` 自动重查），
> 或自己实现时务必手动重挂信号。**切主题必须手动重查。**

### 4.8 动效：尊重系统「减少动态效果」

```cpp
if (PanshiUi::reduceMotionRequested()) { /* 时长归零 / 直接呈现终态 */ }
```

### 5.2 两种安装形态

`install.sh` 自动判断（`/usr/bin` 可写 → 系统级；否则用户级 `~/.local`）：

| | 系统级 | 用户级（只读磐石） |
|---|---|---|
| 二进制 | `/usr/bin/panshi-manager` | `~/.local/bin/panshi-manager` |
| 图标 | `/usr/share/icons/hicolor/scalable/apps/` | `~/.local/share/icons/hicolor/scalable/apps/` |
| desktop | `/usr/share/applications/` | `~/.local/share/applications/` |
| DConfig schema | `/usr/share/dsg/configs/…` ⚠️ | `~/.local/share/dsg/configs/…` |
| systemd | `/usr/lib/systemd/user/` | `~/.config/systemd/user/` |
| `.qm` | `/usr/share/panshi-manager/translations/` | `~/.local/share/panshi-manager/translations/` |

**两处都用 `@PANSHI_BINDIR@` 占位符**（`configure_file` 替换，install.sh 用 `sed` 替换）：

```desktop
Exec=@PANSHI_BINDIR@/panshi-manager
```

> ⚠️ 写死任一绝对路径都会让另一形态的开始菜单失效。
> ⚠️ 用户级安装**不要**跑 `update-desktop-database` / `gtk-update-icon-cache` ——
> deepin 25 的 `dde-application-manager` 会自动监听，手动重建缓存会与 dde-shell
> 同步竞态导致**任务栏卡死**（install.sh 已处理）。

### 5.3 DConfig schema 的路径陷阱

⚠️ **DSG 的配置查找路径硬编码 `/usr/share/dsg`**（`DSG_DATA_DIRS` 等环境变量一律无效）。
系统自己的 schema 都在 `/usr/share/dsg/configs/{dde-launchpad,dde-printer,deepin-ai-daemon,…}`。

本项目默认 prefix 是 `/usr/local` → 装到 `/usr/local/share/dsg/configs` → **DSG 根本不扫那里**：

```
Can't acquire config manager … Can't load resource: /org.deepin.panshi-manager
DConfig is invalid of appid=org.deepin.panshi-manager
```

→ 磁盘监控的启用状态/阈值读写**全部退化为默认值**（配置存不住）。

**修法**：打包必须

```bash
cmake -B build -DCMAKE_INSTALL_PREFIX=/usr
```

`CMakeLists.txt` 已在 prefix ≠ `/usr` 时发 `message(WARNING)`，别忽略它。

### 6.1 四层验证

| 层 | 手段 | 覆盖 | 耗时 |
|---|---|---|---|
| L1 编译期 | `cmake --build` | 类型、Qt6 API 移除、`Q_DECLARE_METATYPE` 缺失 | 秒级 |

## 7. 经验教训（30 条，按成因分组）

> 每一条格式：**症状 → 根因 → 规矩**。
> 带 ⚠️ 的是**已经造成过实际返工**的；其余是「知道了能省一次 debug」。

### 组 A：「文档 / 命名 ≠ 既成事实」必须实测

这是本项目**最贵的一类教训**，五次实证。

---

#### A1. 颜色角色名 ≠ 语义

**症状**：Banner 错误态、状态卡 Danger 徽章、磁盘页 ≥90% 的「已用」大数值
全部渲染成**普通正文黑**，危险语义完全失效。代码写的
`DPalette::TextLively`，看名字像是"活跃/警示色"。

**根因**：`TextLively` 在 DTK 里的语义是「活跃式文本（**不受活跃色影响**）」，
本就不是危险色。**角色名不承诺语义**。

**规矩**：
- 任何"这个颜色角色对不对"的疑问，用探针**打印实际 RGB 值**确认，不要靠名字推断
- 改 `semanticColor()` 映射后**必须**跑 `panshi-colorprobe` 看采样值
- 记忆里"DTK 某某角色是某某色"这类结论，落地前先复核

---

#### A2. 图标名在库里不存在

**症状**：用户截图里 7 个侧栏图标只有「磁盘空间」是彩色，其余是**灰色细线小箭头**。

**根因**：**7 个图标名里 5 个在 DCI 图标库（`/usr/share/dsg/icons/<主题>/`，11 个主题）
中根本不存在**。`DIconTheme::findQIcon()` 返回空 `QIcon` →
`navIcon()` 一路回落到 `QStyle::SP_FileDialogNewFolder` → 渲染成灰色标准图标。
**不是样式问题，是名字写错。**

**规矩**：
- 用图标前先 `panshi-dciquery <name>` 确认存在性（位置参数）
- 任何"图标显示成 X"的缺陷报告，**第一步是查名字存在性，不是调样式**
- 库图标语义不够时直接自带 SVG（见 3.7），别在"换哪个库图标"上死磕

---

#### A3. 配置键的 appid 写错

**症状**：每次运行打一条 `key "enable-animations" not found in org.deepin.dde.appearance schema`
警告，且「减少动态效果」开关对本应用**完全无效**（静默失效，无编译告警）。

**根因**：appid 错了，不是键名错。在本机 ostree 部署里展开该发行版全部 gschema 后确认：
- `com.deepin.dde.appearance`（真实 id，**没有** `org.deepin` 前缀）只有 6 个键
  （`background-uris` / `wallpaper-uris` / `opacity` / …），**一个动画键都没有**
- `enable-animations`（type=b，默认 true）实际住在 DDE 对 GNOME 的包装 schema
  **`com.deepin.wrap.gnome.desktop.interface`**

**规矩**：
- 查 deepin 配置键的**正确路径**：展开
  `/ostree/deploy/deepin/deploy/*/usr/share/glib-2.0/schemas/*.gschema.xml` 搜键名。
  比在运行中的系统上 `dconf dump` 可靠（本机 DConfig 根本不可用）
- `DConfig::value(k, default)` **无法区分「键存在且为 false」与「键缺失」** ——
  必须显式查 `keyList()`

---

#### A4. DTK6 已移除的 API（编译错误，不是警告）

**症状**：`DApplication::setThemeType(...)` 写上去是**编译错误**。

**根因**：DTK6 把它 `#if DTK_VERSION < 6` 包掉了。**等价物是 `setPaletteType()`**。

**规矩**：Qt5 → Qt6 迁移期，**新增代码当轮就编译**，否则缺陷潜伏到下次有人编译为止。
已知移除清单：`qMakeUnique` / `QRegExp` / `QStringRef` / `endl`；
`qAsConst` 已 deprecated。

---

#### A5. 控件"某个 setXxx 调了但没效果"

**症状**：`DProgressBar` 设为 18px 高后，内嵌 format 文字**仍不显示**。

**根因**：**DTK6 的 DProgressBar 样式不绘制内嵌 format 文字** ——
`setTextVisible(true)` 在继承链上有效，但样式层未实现 `CE_ProgressBarLabel`。

**规矩**：控件某个 setter 无效时，**先查样式层是否实现**，不要先怀疑尺寸/裁剪。
**文档写有该绘制入口 ≠ 实现存在。**

---

### 组 B：静默失效（无编译告警、无日志）

---

#### B1. 「注册类方法」漏调

**症状**：6 个页面里只有 2 页的 `showFeedback()` 有效，其余 4 页操作成功/失败**没有任何提示**。
日志里什么都没有，代码看起来完全正确。

**根因**：`setFeedbackBanner()` 从没被调。banner 为 `nullptr` 时 `showFeedback()`
**静默跳过、不阻断流程**。

**规矩**：
- **排查"反馈不出现 / 高亮不触发 / 窄窗布局错乱"，第一步永远是查有没有调注册**
- 组件层的注册点要在**页面构造时**调，漏调无任何编译告警
- 复制粘贴页面代码时，**注册点是最容易漏的一类**（因为它不在控件链上）

---

#### B2. `QTableWidget` 的 `setHorizontalHeaderLabels()` 不补列数

**症状**：`setItem()` **静默失败** —— 不报错、不崩，`item()` 返回 `nullptr`。

**根因**：Qt6 中给 3 个 label，`columnCount()` **仍是 0**。

**规矩**：**必须先 `setColumnCount()`** 再设 header labels 和 item。
本项目三处建表恰好都先设了列数（`makeTable` 走 `setColumnCount`；
备份/部署页走 `QTableWidget(0, 6)`），**线上没踩到** —— 已在 `makeTable` 就地留注释防后人。

---

#### B3. `Qt::UniqueConnection` 不支持 lambda

**症状**：`connect` **静默失败**，无任何警告。

**规矩**：需要 `UniqueConnection` 时用成员函数槽，或中间过一层普通函数槽。

---

#### B4. 外层 `ScrollBarAlwaysOff` 吞掉溢出

**症状**：窄窗下第 4 张卡的数值被截、同容器内的开关被推出视口**不可见**。

**根因**：`Ui::makeScrollArea` 设了 `setHorizontalScrollBarPolicy(Qt::ScrollBarAlwaysOff)`
→ 内层溢出**被静默裁掉且不可达**。这是「外层容器静态裁剪」，
与"Qt 不重算 sizeHint"是不同层级的问题，**调列宽/省略都无效**。

**规矩**：两道防线缺一不可 ——
① 每张卡有**显式最小宽度**（`Size::StateCardMinWidth` 168）；
② 卡片行按可用宽度**自动折列**（`PanshiResponsiveCardRow`），永不横向溢出。

---

#### B5. `QStackedWidget` 隐藏页不跟随 resize

**症状**：保护页 3 卡首次进入竖排单列，**手动拖一次窗口**才弹回 3 列。

**根因**：隐藏页首次 `show` 时 `resizeEvent` 采到的往往是**尚未布局的尺寸**（实测 viewport ≈100px），
算出 1 列后**粘住**（之后切页不再触发 resizeEvent）。

**规矩**：响应式必须走 `BasePage::registerResponsiveCardRow(...)`，
基类同时监听 viewport 的 Resize **与** showEvent，保证两条路径都会重算。
**"读自身宽度"会自锁** —— 卡片行宽度受列数影响，须用 viewport 宽度作输入。

---

#### B6. `Ignored` 尺寸策略被兄弟项吸干

**症状**：总览页「系统信息」四行的值**整体消失**。

**根因**：`ElidedLabel` 曾用 `QSizePolicy::Ignored` —— 它在布局分配中 sizeHint 记 0，
与带 `stretch=1` 的兄弟项（`PanshiRow` 左文本列）同处一行时，富余宽度全被文本列吸走，
本控件被分到 0 宽、什么都不画。

**规矩**：改回 `Preferred` + `minimumSizeHint()` 返回 24。
最小宽可忽略、窄时可压窄省略、宽裕时按自然宽完整显示。

---

#### B7. 自激循环（写盘 → 监听 → 刷新 → 再写盘）

**症状**：监控未开启时，磁盘页数据区**一直闪屏**。

**根因链**：`rebuildIndex()` 在**无任何日记录**时仍回写一份**空** `index.json`
→ mtime 变化 → `QFileSystemWatcher::directoryChanged` → 400ms 防抖 →
`requestRange` → `onRangeLoaded` → `rebuildSpikeSet` → `loadIndex` → 又 `rebuildIndex` → **死循环**。
每轮 `setLoading` + 重启图表动画。监控开启后后台持续写入使索引稳定，循环自然终止 ——
**所以只在未开启时出现**。

**修法**：`if (!summaries.isEmpty()) writeIndex(idx);`

**规矩**：
- 遇到"只在某个状态下出现"的缺陷，顺着**自激回路**查
  （`写盘 → 文件监听 → 刷新 → 再写盘`），**别停在触发点**
- 排除过的误判记下来别再走一遍：① 监听不存在的路径（`historyDir()` 有 `mkpath`）
  ② 容器 overlayfs 导致 watcher 不可靠（实测是 ext4）③ `requestRange` 里有写操作（只读）
  ④ `ScanOverlay` 自带定时器（没有）

### 组 C：验证方法论

---

#### C1. 验证脚本不许自己骗自己 ⚠️（本项目最有价值的一条）

**症状**：缺陷明明存在，探针却报 PASS。

**根因**：`QCoreApplication::exit(1)` 在**纯同步 `main()`**（无事件循环）里
**只设事件循环返回值**，会被后面的 `return 0` 直接覆盖。

**规矩**：
```cpp
// ❌ 缺陷存在时照样 PASS
QCoreApplication::exit(1);
return 0;

// ✅
std::exit(1);      // 或 return 1（同步 main 里 return 是可靠的）
```
- **验证脚本自己骗自己，比没写脚本更危险** —— 它会让人以为已经验证过了
- **断言前先校验前置条件**，否则 nullptr 崩溃掩盖后续全部断言

---

#### C2. 修复类缺陷必须双向验证

**规矩**：

```
临时回退修复 → 探针必须 FAIL   ← 证明探针真的能抓到这个缺陷
恢复修复     → 探针必须 PASS
```

再加一条**反向对照**防"修过头"：
例 —— 修「空索引不写盘」要配一条「**有数据时仍必须写盘**」。

---

#### C3. 单一指标会骗人，评估视觉质量至少要两个指标

**症状**：实测某库图标饱和度 S90 = 0.94（看着很艳），用户照样说"看不清"。

**根因**：它是"大面积白底 + 少量高饱和 accent" —— 彩占比仅 **30%**、彩像素均明度 0.83。
20px 下几乎不可见。

**规矩**：
- **「艳不艳」和「看不看得见」是两件事**，两个指标都要
- 判据：**S90 ≥ 0.15 且 彩占比 ≥ 0.40**（着色像素 / 全部不透明像素）
- 选指标的标准：**能反映真实成因**的指标。只测"文件存在"测不出"20px 下糊掉"

---

#### C4. 图标必须在真实尺寸下看

**症状**：首版 `layers-snapshot` 用等宽三条横条，20px 下与**汉堡菜单按钮**无法区分。

**根因**：64px 放大图看不出这类问题。

**规矩**：**任何视觉判断都在真实使用尺寸下做**。侧栏 20px、徽章 16px、
正文 18px、大数值 28px —— 各自的判据不同，不能互相外推。

---

#### C5. 匹配命令输出必须考虑本地化

**症状**：`sudo -n` 失败后的 `pkexec` 回退**在中文环境下永不触发**。

**根因**：`sudo` 的「需要密码」提示随 `LANG` 变化 ——
英文是 `"sudo: a password is required"`，中文是 `"sudo: 需要密码"`
（**不含任何拉丁字母的 "password"**）。原实现只匹配 `"password"`。
而中文恰是本项目主语言与默认 locale，等于**主路径失效**。
症状：英文实例一切正常，中文实例的 root 操作直接失败 Banner。

**规矩**：
```cpp
bool needsPassword(const QString &s) {
    return s.contains("password", Qt::CaseInsensitive)
        || s.contains("passphrase", Qt::CaseInsensitive)
        || s.contains(QString::fromUtf8("密码"));
}
```
- **用英文环境测多语言应用，恰好漏掉这类缺陷**
- 刻意**不**匹配 `user is not in the sudoers file` ——
  该用户本就无权，回退只是白等授权框

---

#### C6. 验证环境的限制要显式写进工具输出

**症状**：差点误判"换了图标但截图没变"是 bug。

**根因**：本机 DConfig 不可用 → DTK 读不到图标主题名 →
`DIconTheme::findQIcon()` 对**任何**名字都返回空 → 侧栏截图里每行都是同一个 QStyle 兜底图。
**证据**：换掉图标名后截图 md5 完全不变。

**规矩**：
- 探针输出里**显式声明**哪部分可信、哪部分不可信
  （`panshi-navshot` 现在会输出"截图只能看排版，图标长相看 iconsheet"）
- 不可信的环境限制要写进文档每次复测前重读（见 `挂起项总看板.md` §六）

---

#### C7. 区分「谁的锅」要拿证据

**症状**：运行时有两条不明来源的警告。

**根因与手法**：
- `setHighDpiScaleFactorRoundingPolicy must be called before...`
  → **不是我们的代码，也不是 DApplication**。证据链：全项目 grep 无调用 →
  `nm -D --undefined-only` 扫全部系统库无引用者 → 写 10 行最小程序复现（只构造 `DApplication`）→ **不报**。
  且该 API 在 Qt6 已是 **no-op**（高 DPI 恒开）。→ 上游噪声，**不需要"修"**，
  也不建议为此在 main 里加调用（既消不掉别人的警告，又引入一个 Qt6 无意义的调用）
- `DConfig is invalid` → 见 §5.3，是打包前缀问题不是代码问题

**规矩**：
- **最小复现程序**是判定"是否由某个库触发"最快的手段
  （10 行代码就避免了去 DTK 源码里挖）
- 分清「代码缺陷」/「环境限制」/「上游噪声」三类，别混在一起改代码

### 组 D：继承与布局

---

#### D1. 删除继承来的控件 = 制造悬垂指针

**症状**：接管 `DAboutDialog` 时，最初做法是「删除」基类内容
（`setParent(nullptr)` + `deleteLater`），一 `show` 就 segfault。

**根因**：那些控件的指针记在 DTK 私有的 `DAboutDialogPrivate` 里，
界面显示期间随时会被访问 —— 控件没了就是悬垂指针。

**规矩**：要"换掉"基类内容就用 **`setVisible(false)`** ——
指针仍有效，DTK 照常访问，只是不显示。
**除非你确知私有类不持有它的指针（本项目里我们不知道）。**

---

#### D2. 隐藏"全部"直接子控件会连带藏掉不该藏的

**症状**：① 关闭按钮消失；② 对话框"透明度太高"（壁纸整片透进来）。

**根因**：`DAboutDialog` 的直接子控件有**两个**：内容区 + **`Dtk::Widget::DTitlebar`**
（含 `DTitlebarCloseButton`、标题文字、窗口菜单）。「隐藏全部」把 DTitlebar 一起藏了 ——
关闭按钮消失；而 `DDialog` 自身背景是**半透明的**（圆角 + 阴影设计），
内容区一藏就透了。

**规矩**：
```cpp
for (QObject *c : dlg->children()) {
    if (c->metaObject()->className() == QStringLiteral("Dtk::Widget::DTitlebar"))
        continue;                       // 按类名跳过
    if (auto *w = qobject_cast<QWidget *>(c)) w->setVisible(false);
}
content->setAutoFillBackground(true);    // 补不透明底色
```
⚠️ 底色用 `palette().color(QPalette::Window)`（body 的调色板继承自对话框 →
切暗色时 Qt 自动发 PaletteChange 重绘）。**不要手动 `setPalette`**，否则切主题留旧色。

---

#### D3. 接管别人家布局：`setMinimumHeight` 比 `resize()` 可靠

**症状**：`resize(520, 480)` 后信息卡仍被压到 65px、行文字全叠在一起。

**根因**：`body` 的 sizeHint 是 480，但对话框只给 290；
**布局把不足的高度优先压给可压缩的子项**，`resize()` 的请求值被压回。

**规矩**：硬约束用 `setMinimumHeight`，不用 `resize()`。

---

#### D4. 修「Qt 不重算 sizeHint」要先分清**到底谁被压**

**症状**：关于页「平台」行第二行被裁。排查经历**三次误判**：
1. 以为是 measure 顺序问题（先量高后定宽）→ 改了，md5 不变
2. 加 `WrapHeightFixer` 监听 Resize 补 `heightForWidth` → 探针显示 `minH=0 hfw=42`，
   **补正根本没触发**（首次 Resize 时布局未稳定，算出的需求偏小，之后再无 Resize）
3. showEvent 末尾显式补一轮 → 标签对了（`minH=42 hfw=42`），
   但**行容器** `sizeHintH=92 h=35` —— 真正被压的是行
4. 给行设 `QSizePolicy::Fixed` + `setMinimumHeight(sizeHint())` → 行高补上了，
   **但行与行重叠**（卡片高度按各行原始 sizeHint 算，拉高行却不拉高卡片）

**最终解法（治本）**：**让文字本来就放得下** ——
默认宽度 520 → 600（`kAboutMinWidth`），精简平台文案（去掉冗余的"支持""基于"），
`wordWrap` 保留作兜底。

**规矩**：
- 探针打印**三个值**（标签 minH/hfw/h + 容器 minH/sizeHint/h）**一步定位**，省掉三轮猜测
- **强行 `setMinimumHeight` 打破布局的原始假设会导致"重叠"这类更糟的副作用** ——
  优先从"让内容放得下"入手，而不是与布局较劲

---

#### D5. 主题切换：两个信号时序不同

**症状**：应用内「≡ → 主题」切深色，界面**半新半旧** ——
直接 QPainter 取色的侧栏文字按新主题变白，QSS 背景与 DLabel 仍是旧主题 → **白底白字，标签集体消失**。

**根因**：信号时序 + `setStyleSheet` 冻结调色板快照。

**规矩**：
1. 挂 **`applicationPaletteChanged`** 而**不是** `themeTypeChanged` ——
   后者发出时 DTK 的调色板替换**尚未完成**（`singleShot(0)` 在切深方向依旧太早）
2. 组合五步（缺一不可）：
   ```cpp
   qApp->setStyleSheet(QString());                              // ① 拆样式表调色板快照
   qApp->setPalette(DGuiApplicationHelper::instance()->applicationPalette());  // ② 重灌
   qApp->setStyleSheet(panshiStyleSheet());                     // ③ 重设
   for (QWidget *w : QApplication::topLevelWidgets()) {
       w->style()->unpolish(w); w->style()->polish(w);           // ④ 强制全树重取色
       // ⑤ ⚠️ 深度递归 update()：顶层 update() 只刷新自身及已知脏区，
       //    **隐藏页**（QStackedWidget 里未激活的）的自绘卡片不会被标脏
   }
   ```
3. **themeType（系统主题）≠ paletteType（应用调色板）**：
   只设 `paletteType` 时文字（走 paletteType）变暗了，但容器自绘（走 `applicationPalette()`）
   仍是浅底（实测暗色 bg 仍 `#f8f8f8` 而文字已变白）

---

#### D6. `Q_OBJECT` 与命名空间前置声明

**症状**：cpp 里按完整类型使用时报 incomplete type。

**根因**：类型前置声明写在 `namespace PanshiUi` **内部**，
会声明出 `PanshiUi::QPropertyAnimation` 这种**不存在的嵌套类型**。

**规矩**：前置声明必须在 `namespace` **外**（`components.h` 有注释标注）。

---

#### D7. D-Bus：总线名允许连字符，接口名不允许

**规矩**：服务名与接口名**必须分开命名**：

```cpp
const QString navService   = "org.deepin.panshi-manager.disknav";   // 可含连字符
const QString navInterface = "org.deepin.panshi.disknav";           // ⚠️ 不可含
bus.registerObject("/disknav", navInterface, nav, ExportAllSlots);
//                  ↑ 需显式传接口名，否则默认用类名导致调用失败
```

### 组 E：数据与持久化

---

#### E1. JSON 字段用单字母 key

`DiskSample` 的历史存储动辄几万条记录，字段名是体积的线性放大器。
现状：`ts` / `h`（hotDirs）/ `n` / `c` / `dc`（drillCache）。
新增字段沿用，**读取必须容忍缺失**（老记录没新字段 → 返回中性默认值）。

---

#### E2. 原子写：临时文件 + rename

`writeJsonAtomic()` 走临时文件 + rename。
**理由**：监控进程写 `index.json` 时，GUI 侧可能正在读 —— 直接覆盖会读到半个文件。

---

#### E3. 缓存 TTL 要短且可解释

| 缓存 | TTL | 原因 |
|---|---|---|
| 快照大小 | 60s | 变化慢，但 60s 内重复计算纯属浪费 |
| du 结果 | 30s | 单次 du 可能几秒，页面切换重复计算体验差 |

OSTree 树缓存另存 `~/.cache/panshi-manager/tree_*.json`（与 Python 原版一致），
二次启动直接读缓存不再遍历系统树。

---

#### E4. `du` 不能用 `-x`

`df -B1 /` 只反映根分区，但目录归属跨 `/var` / `/home` / `/usr` 等独立挂载/overlay。
**用 `du -x` 会漏掉它们** → 合计与 `df` 的差值被夸大。

另：`du -s` 与 `--max-depth` **冲突**，会直接警告无输出（已实测）。

---

#### E5. 统计口径要在文档里写明

- **容量/已用**：`df -B1 /`
- **目录归属**：`du`（跨所有挂载）
- **快照占用** = 数据目录物理大小 + **独占** OSTree 对象大小（跨快照去重）

→ 由于多挂载重复视图，目录合计**可能大于** `df` 已用；**逐日 diff 定位不受影响**。

### 组 F：工程习惯

---

#### F1. 增量构建与陈旧产物会掩盖缺陷

**症状**：用户跑 `./build/panshi-manager`，但当天所有改动都没进去，
看到的现象是旧版本产生的。

**根因**：`build/` 里**没有 `CMakeCache.txt`** —— 陈旧产物目录。
二进制 3.4MB vs `build2/` 的 30MB，差一个数量级。

**规矩**：
- **改完代码两边都编**（`build/` 与 `build2/` 同源，用户习惯跑 `build/`）
- 判断新不新看**时间戳 + 大小**
- ⚠️ `qAsConst` deprecated 警告就是被增量构建掩盖的 —— **全量重建才暴露**

---

#### F2. 改一处必找复制粘贴处

项目里有多处"同一逻辑写了两份"的历史：
- 侧栏图标名列表在 `mainwindow.cpp` 与 `sidebar.cpp` 注释里各一份
- `makeCopyButton` / `makeCommandRow` 曾各写在 `aboutpage.cpp` 与 `aboutdialog.cpp`
- 错误输出"当前由谁负责"这种元信息，容易在文档、代码注释、实际实现之间分叉

**规矩**：**发现复制粘贴立即收敛到 `common.h` 或 `components.*`**
（这是本项目一贯的"提升到公共层"做法）。两处各写一份必然分叉。

---

#### F3. 改一处可能牵连三层

例：把一个 Qt 原生控件换成 DTK 控件，看似一行改动，实际牵连：
① 头文件替换 ② **objectName 引用者**（若有 QSS 规则依赖它）
③ **依赖该 objectName 的颜色变量**（否则留下死规则 + `-Wunused-variable` 诊断）。

阶段 3-7b 据此把 `style.h` 收敛到只剩 5 个结构性颜色
（`bg` / `sidebar` / `card` / `border` / `textSub`），**不再有任何语义色插值**。

---

#### F4. shell 脚本无执行权限

⚠️ 仓库里的脚本可能没有可执行位 → `bash verify-runtime.sh` / `python3 make-testdata.py`。

---

#### F5. 能编过 ≠ 写对了

`setMinimumHeight(sizeHint())` 编译通过、行高也确实变了 ——
但**行与行重叠**了。编译只保证语法类型，不保证布局语义。
**凡是用"与布局较劲"的方式绕过问题，先想一遍"能不能让内容本来就放得下"。**

---

#### F6. 三条 DTK API 不可凭语义猜

| 想做的事 | 直觉写法 | 实际 |
|---|---|---|
| 列出 DConfig 键 | `cfg->keys()` | **`keyList()`**（写错直接编译失败） |
| 手动切主题 | `setThemeType()` | DTK6 已移除 → **`setPaletteType()`** |
| 单元格无障碍 | "DTK 无接口，需自绘 delegate" | **Qt 原生 `item->setData(Qt::AccessibleTextRole, …)` 即可** |

最后一条是**记忆里长期存在的错误判断**（记为"DTK 无单元格接口"），
2026-10-04 实测推翻。**连自己的记忆都要实测。**

---

#### F7. QSS 优先级高于 DPalette

只要 QSS 里还留着一条颜色规则，该控件就**不会跟主题**。

**规矩**：新增视觉前先问「这个颜色来自哪个 `DPalette` 角色」，
**回答不了就不要写**。

---

#### F8. 读自身宽度会自锁

响应式容器若在 `resizeEvent` 里读 `width()` 来决定自己的布局，
而它的宽度又受自己的布局影响 → 循环依赖。
**必须用 viewport 宽度作输入**（`registerResponsiveCardRow` 已封装）。

## 8. 已知限制与后续

### 8.1 功能限制

| 限制 | 说明 | 影响面 |
|---|---|---|
| **跨分区统计口径** | `df /` 只反映根分区，目录归属跨 `/var` `/home` 等多分区，合计可能大于 df 已用（含 `/ostree` 等多挂载重复视图） | 逐日 diff 定位不受影响 |
| **root 依赖** | 完整扫描依赖 `sudo -n`；未配置时降级为不完整扫描（`complete=false`，时间线灰色） | 后续可接 polkit 规则或改由系统服务运行 |
| **盘符范围** | 目前仅监控系统盘 `/` | 模型已预留 `DiskSample.hotDirs`，可扩展多挂载点 |
| **日内回放** | samples 保留 90 天，已支持日内粒度 | "逐日播放式动画"列为后续增强 |
| **提权自动化不可达** | 助手侧无法输密码 | 需 `pkexec` 授权的分支只能人工复核 |
| **系统级暗色不可达** | DTK6 走 treeland Wayland，不读 gsettings | 但进程内 `setPaletteType(DarkType)` 可强制 |

### 8.2 待人工复核项（代码与自动断言均已闭合）

| 项 | 状态 | 怎么解开 |
|---|---|---|
| **C1** 三态截屏对比 | 待人工 | 造数据后切亮/暗/中间态各截一张 |
| **C5** 暗色整体观感 | 待人工 | 配色值已自动断言，剩观感 |
| `QTableWidget` 单元格无障碍 | ✅ 已结项（2026-10-04） | `panshi-a11y-probe` 9 条断言 |
| O12 侧栏折叠 <1000px | ❌ **用户决策放弃** | 评估后价值有限（920px 实测无挤压） |

> 完整看板见 [`挂起项总看板.md`](挂起项总看板.md)。

### 8.3 已知的技术债

| 项 | 说明 | 建议时机 |
|---|---|---|
| `diskusagepage.cpp` 1729 行 | 明显过大，图表逻辑、表格逻辑、概览统计混在一起 | 下次改磁盘页时拆分（`disksection_*.cpp`） |

## 附录 C 术语表

| 术语 | 含义 |
|---|---|
| **磐石** | Deepin 25 的不可变系统（OSTree 只读根 + 可写层） |
| **可写层** | 临时或永久开启的系统可写层（`deepin-immutable-writable`） |
| **快照（snapshot）** | 备份点（`deepin-immutable-ctl`） |
| **部署（deploy）** | 可启动的系统版本 |
| **DSG** | deepin 的 DConfig 服务，查找路径硬编码 `/usr/share/dsg` |
| **D-Bus 定位转发** | 通知「查看详情」时把日期转给已运行的实例 |
| **注册点** | 本项目核心解耦模式：页面在构造时把「我有什么」注册给基类 |
| **到达后动作** | 跨页跳转 + 等目标页 refresh 完成后再执行的动作 |
| **三档加载** | L1 骨架屏 / L2 局部 spinner / L3 顶部细进度条 |
| **恒等翻译** | 源语言（中文）的 `.ts`，`<translation>` = `<source>` |
| **探针** | 开发期的离屏渲染 + 像素采样 / 结构断言 小工具，不安装 |
| **DCI** | deepin 主题图标（`.dci` 文件），在 `/usr/share/dsg/icons/<主题>/` |
| **彩占比** | 着色像素 / 全部不透明像素 —— 衡量图标「看不看得见」的关键指标 |
| **Treeland** | Deepin 25 的 Wayland 桌面合成器（DTK6 走它） |
