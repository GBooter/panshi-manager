# UI 优化方案 — 策略与设置页（信息架构与布局重设计）

> 前置：阶段 3-3（行式表单 + 反馈/加载迁移）已验收。
> 本文档基于截图 V（2026-10-06）与 policypage.cpp 现状提出**信息架构重排 + 交互联动 + 文案精简**，
> 不改动后端（getCtlConfig / setCtlConfig / config.json 字段全部保持）。

## 一、现状问题清单（对照截图）

### P1 回滚主题被拆散在两个分组（信息架构）
- 「回滚前备份自动清理」在**备份保留策略**组；
- 「升级失败自动回滚」「最大备份部署数」在**磐石系统参数**组。
- 三者同属"更新/回滚"流程，用户无法在一处评估回滚安全整体配置。

### P2 强依赖项未联动（交互）
- 「自动清理超额备份」开关与「备份数量上限」是依赖关系：上限=0（不限）时清理永不触发，
  但开关照常可拨，可形成自相矛盾的配置（开了清理、上限却是不限）。

### P3 文案重复与晦涩
- 「自动清理超额备份」说明："超过数量上限时, 自动删除最旧的普通备份(初始备份永不删除)"
- 「备份数量上限」说明："超过上限后自动删除最旧的普通备份, 释放存储空间"
  → 两句核心信息完全重复，括号"初始备份永不删除"这个**保护点**反而藏在冗余里。
- 后缀「0个(0=不限)」晦涩：0 同时承担"数量"与"开关"双重含义。
- 下拉项「自动删除(默认, 最安全)」的主观标注（最安全）与说明长句叠加，行高过高。

### P4 两种保存模型混用，无任何标注（最大认知负担）
- 组1 三项改动**即时保存**（静默写 ~/.config/panshi-manager/config.json）；
- 组2 三项需点「保存系统参数」+ 管理员权限才生效。
- 页面未标注差异；组2 改动后**切页即被 refresh 覆盖**（阶段 3-3 已知事项），且无"未保存"提示 → 静默丢失。

### P5 权限与风险提示不足
- "需管理员权限"埋在分组说明小字里，无权限用户点保存才报错（Banner）。
- 「升级失败自动回滚」属系统启动安全策略，与普通行同权呈现。

### P6 布局细节
- 两组均 3 行、等宽排列，无主次；
- 数值行（上限/部署数/阈值）无合理范围建议。

## 二、重设计方案

### 2.1 信息架构：按"流程主题"三组重排

```
页头：策略与设置
副标题：备份保留策略与磐石系统参数

┌─ 分组1  备份保留 ──────────── [即时生效] ─────┐
│ 系统升级会自动创建备份（系统内置，不可关闭）。   │
│ 以下策略控制备份保留与清理，避免无限累积。       │
│ ┌ 备份数量上限      [ 10 个 ]              ┐  │
│ │ 0 表示不限；超出后按清理策略处理           │  │
│ └────────────────────────────────────────┘  │
│ ┌ 超限自动清理      [开关] ← 上限>0 才可开 ┐  │
│ │ 仅删除最旧普通备份；初始备份永不删除        │  │
│ └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘

┌─ 分组2  更新与回滚 ────────── [即时生效] ─────┐
│ ┌ 升级失败自动回滚   [开关]                ┐  │
│ │ 失败时回滚到升级前状态，避免系统无法启动    │  │
│ └────────────────────────────────────────┘  │
│ ┌ 回滚前备份清理    [手动清理 ▾]           ┐  │
│ │ 还原前自动创建回滚前备份；回滚成功后按所选   │  │
│ │ 方式清理                                  │  │
│ └────────────────────────────────────────┘  │
│ ┌ 保留旧部署数      [ 1 个 ]               ┐  │
│ │ 升级/回滚时保留的旧系统部署数量            │  │
│ │（默认 1，新备份自动覆盖旧备份）             │  │
│ └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘

┌─ 分组3  磐石系统参数 ─ [需保存 · 需管理员权限] ┐
│ 写入 /etc/deepin-immutable-ctl/deepin-immutable-ctl.conf
│ ┌ 自动刷新阈值      [ 200 MiB ]            ┐  │
│ │ 修改层超过该阈值时自动刷新合并到系统层；    │  │
│ │ 建议 200–1000 MiB                        │  │
│ └────────────────────────────────────────┘  │
│ ┌ 配置文件          /etc/deepin-immutable-  ┐  │
│ │  ...ctl.conf（只读信息行）                 │  │
│ └────────────────────────────────────────┘  │
│                        [ 保存系统参数 ]       │
└──────────────────────────────────────────────┘
```

分组逻辑：
- 组1 = **备份**（数量 + 清理）→ 关联联动；
- 组2 = **回滚全链路**（失败回滚 → 回滚前备份 → 部署数），叙事连贯；
- 组3 = **系统级参数**（阈值 + 配置文件信息 + 保存按钮），天然自成一格，不再单薄。

### 2.2 交互联动：上限与清理开关
- 上限 = 0（不限）→ 「超限自动清理」开关**禁用**，行说明置灰为
  「上限为不限时无需自动清理」；
- 上限 > 0 → 开关恢复可用，说明显示「仅删除最旧普通备份；初始备份永不删除」。

### 2.3 保存模型清晰化
- 组1 / 组2 组头右侧：`PanshiBadge(tr("即时生效"), Semantic::Muted)`；
- 组3 组头右侧：保留「保存系统参数」按钮，说明改为
  「需管理员权限；修改后点击保存生效」；
- 组3 任一控件改动 → 保存按钮转强调态 + 组头出现
  `PanshiBadge(tr("有未保存修改"), Semantic::Warning)`；保存成功清除。
- （可选增强，需 mainwindow 配合）切页前若有未保存修改 → 确认对话框；
  BasePage 增加 `virtual bool hasUnsavedChanges()`，mainwindow switchTo 前查询。

### 2.4 文案精简（对照表）
| 位置 | 现文案 | 新文案 |
|---|---|---|
| 组1说明 | 磐石系统升级时会自动创建备份(系统内置, 不可关闭)。应通过以下策略避免备份无限累积。 | 系统升级会自动创建备份（系统内置，不可关闭）。以下策略控制备份保留与清理，避免无限累积。 |
| 上限行说明 | 超过上限后自动删除最旧的普通备份, 释放存储空间 | 0 表示不限；超出后按清理策略处理 |
| 清理开关说明 | 超过数量上限时, 自动删除最旧的普通备份(初始备份永不删除) | 仅删除最旧普通备份；初始备份永不删除 |
| 上限后缀 | 个 (0=不限) | 个（0 表示不限） |
| 回滚前备份下拉项 | 手动删除(默认, 最安全) / 重启3次正常后自动删除 | 手动清理（默认）/ 重启 3 次正常后自动清理 |
| 部署数说明 | （默认1, 新备份自动覆盖旧备份） | （默认 1，新备份自动覆盖旧备份） |
| 阈值说明 | 修改层超过该阈值时自动刷新合并到系统层 | 修改层超过该阈值时自动刷新合并到系统层；建议 200–1000 MiB |

### 2.5 权限提示（可选增强）
- refresh 时检测当前用户是否可写目标 conf（root 或 sudo -n true 探测）；
  不可写 → 组3头部 `PanshiBadge(tr("当前无管理员权限"), Semantic::Warning)` + 保存按钮禁用。
- 保守起见可不做预检测（避免误判），保留"保存失败 Banner"兜底 —— 二者择一，默认后者。

### 2.6 布局细节
- 数值控件统一最小宽度（现状已 OK），说明保持 ≤2 行；
- 「配置文件」用 PanshiRow 只读信息行（addControl 传 minW=0 + ElidedLabel），
  路径比组头小字更醒目、可复制。

## 三、落地清单（policypage.cpp / .h）

| 改动 | 涉及 | 说明 |
|---|---|---|
| 三组重排 | 构造顺序 | 行顺序调整 + 组头徽章 |
| 上限/清理联动 | m_spinMax valueChanged | 0→禁用开关并改 desc；>0→恢复 |
| 组头徽章 | PanshiBadge | 即时生效 ×2；未保存修改（动态） |
| 保存按钮动态态 | bSave | dirty 时 setEnabled/强调；保存成功清除 |
| 只读信息行 | PanshiRow | 配置文件路径 |

字段兼容性：config.json（auto_prune / max_snapshots / rb_auto_clean）与
系统 conf（auto-rollback-on-failure / max-backup-deploys / auto-refresh-size-threshold）**全部不变**。

## 四、验证点
1. 上限=0 时开关灰显且说明切换，>0 恢复；
2. 组3 改动后「有未保存修改」徽章出现、保存按钮强调；保存成功徽章消失；
3. 切页返回不丢失已保存配置（未保存场景按可选增强是否启用）；
4. i18n：translations 需同步更新（本项目文案改动须走 translations 流程）。
