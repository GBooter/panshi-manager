## 1. 项目概述

磐石设置是 Deepin 25 磐石系统（OSTree 只读根 + 可写层）的系统管理工具。
原项目为 PyQt6 实现，本仓库为 **C++ / Qt6 / DTK6 原生重写版**，完美融入 DDE 桌面环境，
支持亮/暗主题自动切换与 X11 / Wayland。

### 1.1 功能一览

页面标识与导航顺序见 `src/mainwindow.h` 的 `enum class PageId`（强类型，取代了此前的裸下标）：

| 页面 | 功能 |
|---|---|
| 总览 | 磐石保护状态、可写层、快照统计、仓库占用、系统信息、快速操作 |
| 磁盘空间 | **持续监控系统盘空间**：时间线展示每日占用变化（近 7 天 ~ 一年）、异常增长定位到文件夹/文件、容量预测、告警通知、排除目录、存储预算控制（后台 systemd user 服务） |
| 系统保护 | 只读保护状态、永久/临时开启/关闭可写层 |
| 备份与版本 | 备份快照 + 系统版本（部署）合并：快照列表/创建/删除/还原、可启动版本列表/删除 |
| 系统更新 | 检查更新、原子升级、清理缓存 |
| 策略与设置 | 备份保留策略（应用级·即时保存）+ 磐石系统参数（系统级·显式保存） |
| 关于 | 应用信息、技术说明、常用命令 |

> 侧栏按「概览 / 系统维护 / 设置」三组呈现，顶部带**设置搜索框**
> （输入即列出匹配的设置项，回车/点击跳转并高亮目标行）。

### 1.2 技术栈

- C++17、Qt 6（Core/Gui/Widgets/Concurrent/Svg/**DBus**）
- DTK6（Dtk6Core / Dtk6Gui / Dtk6Widget）
- DConfig（系统配置）、systemd（用户级定时任务）、D-Bus（单实例定位转发、系统通知）
- 后台命令：`df` / `du` / `ostree` / `deepin-immutable-ctl` / `systemctl` / `gio`

## 2. 环境与依赖

### 2.1 构建依赖（Deepin 25）

```bash
sudo apt update
sudo apt install -y cmake g++ make pkg-config
sudo apt install -y qt6-base-dev          # Qt6 Core/Gui/Widgets/Concurrent/DBus
sudo apt install -y qt6-svg-dev           # Qt6::Svg
sudo apt install -y libdtk6core-dev libdtk6gui-dev libdtk6widget-dev
sudo apt install -y qt6-tools-dev-tools   # 可选：lupdate / lrelease（翻译）
```

包名搜索备用：

```bash
apt-cache search qt6 | grep -iE "svg|base-dev"
apt-cache search dtk6 | grep -i dev
```

### 2.2 构建

```bash
cd panshi-settings-dtk
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

### 2.3 安装（需 root）

```bash
sudo cmake --install build
```

安装内容：
- 二进制 → `/usr/bin/panshi-manager`
- 图标 → `/usr/share/icons/hicolor/scalable/apps/panshi.svg`
- 桌面文件 → `/usr/share/applications/org.deepin.panshi-manager.desktop`
- DConfig schema → `/usr/share/dsg/configs/org.deepin.panshi-manager/`
- systemd 用户单元 → `/usr/lib/systemd/user/panshi-monitor.{service,timer}`
- 翻译 → `qt_add_translations()` 安装的 `panshi-manager_<locale>.qm`（见 §9）

### 2.4 命令行参数

| 参数 | 说明 |
|---|---|
| （无） | 正常启动 GUI |
| `--monitor` | 无界面后台监控模式，执行一轮监控周期后退出（由 systemd user timer 拉起） |
| `--show-disk <YYYY-MM-DD>` | 启动并跳转到磁盘占用页、选中指定日期（通知"查看详情"使用）；若已有实例运行则经 D-Bus 转发后退出 |

### 3.1 UI 组件层与「注册点」范式

`BasePage` 提供四个注册点，页面在构造时把自己的结构交上去，
**共享逻辑只与基类对话**，从而避免组件层反向依赖具体页面：

| 注册点 | 用途 |
|---|---|
| `registerResponsiveCardRow(row, scrollArea, hPadding)` | 卡片行宽度喂入（viewport Resize + `showEvent` 双路径，解决隐藏页首次显示采不到真实尺寸） |
| `setFeedbackBanner(banner)` / `showFeedback(s, text, autoHide)` | 页面级反馈宿主（`masterswitch` 的共享逻辑经此写入结果） |
| `runAsyncQuiet(fn, onDone)` | 完全不碰整页遮罩的静默刷新（切标签预读） |
| `registerSearchTarget(key, row, scroll)` / `highlightSetting(key)` | 设置搜索定位（滚动 + 高亮） |

新增组件请遵守：颜色取自 `DPalette`、度量取自 `tokens.h`、文案 `tr()` 包裹、
动效遵守 `reduceMotionRequested()`。组件层默认**不使用 `Q_OBJECT`**
（唯一例外 `PanshiRow`：高亮动画需 `Q_PROPERTY`，见其头文件注释）。

### 3.2 跨页跳转携带动作（「到达后动作」队列）

总览页的三个快速操作是**一次意图**，不该拆成"跳页 + 用户自己再找一次按钮"。
但目标页的 `refresh()` 是异步的，跳页后立即执行动作会踩两个坑：

1. 动作作用在尚未刷新的旧数据上；
2. 动作入口普遍带 `if (m_running) return;` 防重入守卫，refresh 在途时动作**被静默丢弃**
   ——用户观感是"点了没反应"。

因此 `MainWindow` 提供两个重载：

```cpp
void gotoPage(PageId id, std::function<void()> afterArrive);
void gotoPage(PageId id, SubPageId sub, std::function<void()> afterArrive);
```

动作挂到目标页的空闲信号上，refresh 结束后执行：

| 环节 | 实现 |
|---|---|
| **空闲信号** | `BasePage::idleReached()` —— 基类在 `runAsync`/`runAsyncQuiet` 层统一用 `m_inFlight` 计数，归零时发出。**`onDone(res)` 必须排在 `endTask()` 之前**，否则"完成回调里再起一段"的页面（总览页快速状态 → 慢速统计）会在半程误发。 |
| **复合页** | `VersionManagementPage::isBusy()` 覆写为聚合两个子页（它的 `refresh()` 只是转发，自身计数恒为 0），并把子页的 `idleReached` 转达上来。 |
| **立即执行** | `!target->isBusy()` 时直接执行（`UpdatePage::refresh` 是空实现，等一个永不到来的信号会卡死）。 |
| **超时兜底** | `kArrivalTimeoutMs = 4000`；后端阻塞导致页面迟迟不空闲时仍放行动作。 |
| **后到覆盖先到** | 同一时刻只保留一个待执行动作，覆盖时解绑旧宿主。 |
| **切页作废** | `switchTo()` 开头 `flushArrivalAction(false)` —— 用户改点侧栏时旧动作不再迟到弹出。 |
| **退出作废** | `closeEvent()` 里 `flushArrivalAction(false)`（不执行，只解绑）。 |

页面侧的**动作契约**：各页暴露一个 `Q_INVOKABLE` 方法供跨页调用
（总览页不持有目标页头文件，且这些入口是页面私有实现）：

| 页面 | 对外方法 | 内部动作 |
|---|---|---|
| `VersionManagementPage` | `requestCreateSnapshot()` | `showSubPage(0)` → 转发 `SnapshotsPage::onCreate` |
| `UpdatePage` | `requestCheckUpdate()` | `onCheck()` |
| `ProtectionPage` | `highlightEnableProtect()` | 滚入视野 + `m_rowEnable->flashHighlight()` |

> 保护页只做**定位高亮**、不自动执行：关闭可写层是危险操作，跨页跳转负责
> "把用户带到正确的地方并指出那一行"，不代替用户做决定。

> 与「设置搜索」互不干扰：搜索落地走 `gotoSetting()` → `switchTo()` + `highlightSetting()`，
> 不经到达动作队列。

### 3.3 控件层：DTK 控件优先（阶段 3-7b 收尾）

**原则**：能用 DTK 控件就不用 Qt 原生控件 —— 前者自动跟随 deepin 主题、
圆角与动效规范，后者需要额外的 QSS 才能勉强对齐，且主题切换时容易失配。

阶段 3-7b 把磁盘页最后一批 Qt 原生控件替换为 DTK 对应物，**全部保行为**：

| Qt 原生 | DTK 替代 | 关系 | 注意 |
|---|---|---|---|
| `QProgressBar` | `DProgressBar` | **继承** `QProgressBar` | 仅覆写 `sizeHint`/`minimumSizeHint`；`setFormat`/`setTextVisible`/`setRange`/`setValue` 全部沿用，零风险 |
| `QDoubleSpinBox` | `DDoubleSpinBox` | **继承** `QDoubleSpinBox` | 新增 `setAlert()` 等 DTK 扩展；`setDecimals`/`setRange(double,double)`/`valueChanged(double)` 沿用 |
| `QListWidget` | `DListView` | **继承** `QListView` | ⚠️ **不自带模型**（与 `QListWidget` 的便利模型不同），需配 `QStringListModel` 并 `setModel()`；取当前行用 `currentIndex().row()`（无选中返回 -1） |
| `QPushButton` | `DPushButton` | 兄弟类（无继承） | `Ui::button()` 本就返回 `DPushButton*`，成员声明若写成 `QPushButton*` 会丢失 DTK 语义（靠向上转型才编过）——属**声明债**，应改 |
| `QCalendarWidget` | *（DTK 无日历控件）* | — | 保留 Qt 原生；但可用「**单日历两次点击定区间**」范式收敛交互（见下） |
| `QTableWidget` | *（DTK 无等价表格）* | — | **有意保留**（设计方案 §5.2 第 6 条允许；迁 `DListView` 需手写 `QAbstractTableModel` + delegate，风险大于收益） |

**单日历区间选择范式**（`DiskUsagePage::onOpenCustomRange`）：

传统做法是并排/纵排两个日历（起 + 止），但两者相互约束要靠回调里互相比大小，
无效点击会让「日历高亮」与「摘要文字」状态分叉。改为**一个日历 + 两次点击**：

```
初值 complete=true
第 1 次点击 → from = to = d，complete = false
第 2 次点击 → d < from ? from = d（改起点，仍等终点） : to = d，complete = true
```

关键：**摘要文字的唯一数据源是 `from`/`to` 状态**，不再读 `calendar->selectedDate()`
—— 从结构上消除分叉。区间状态用局部 `struct` + `std::shared_ptr` 承载、lambda
按值捕获，并把连接挂到对话框（而非长生命周期的 `this`），避免悬垂引用隐患。

**连带清理**：控件换掉后 `objectName` 若无引用者，其 QSS 规则与**依赖它的颜色变量**
都要删（否则留下死规则 + `-Wunused-variable` 诊断）。阶段 3-7b 据此把
`style.h` 收敛到只剩 5 个结构性颜色（`bg/sidebar/card/border/textSub`），
**不再有任何语义色插值**。

### 4.1 分层

└──────────────┬───────────────┘   └────────────┬───────────────┘

### 4.2 线程模型

- **backend.h 全部为同步函数**，由页面经 `BasePage::runAsync(fn, onDone)` 在
  `QtConcurrent` 工作线程执行、主线程回调；`CommandResult` 返回命令输出。
- **DiskScanner** 基于 `QProcess` 流式解析 `du` 输出（不阻塞 UI），信号
  `progress / topLevelFinished / drillFinished / scanFinished` 实时回传；
  `setAsRoot + RootPolicy`（AutoNoPrompt=自动扫描仅 sudo -n；AllowPrompt=手动扫描可 pkexec）。
- **DiskHistoryStore::requestRange** 在 QtConcurrent 工作线程逐日读取，
  `rangeProgress / rangeLoaded` 信号回传；requestId 支持取消与防抖；内存 LRU 缓存跨线程加锁。

### 4.3 单实例与 D-Bus 定位转发

- `DApplication::setSingleInstance("org.deepin.panshi-manager")` 保证单实例。
- 通知"查看详情"拉起 `panshi-manager --show-disk <date>`：
  1. 若应用未运行 → 冷启动并直接定位；
  2. 若已运行 → 新实例注册 D-Bus 服务 `org.deepin.panshi-manager.disknav` 失败，
     改为调用运行中实例的 `org.deepin.panshi.disknav.ShowDisk` 方法后退出。
- ⚠ 注意：**D-Bus 总线名允许连字符，接口名不允许**。服务名与接口名必须分开命名
  （`org.deepin.panshi-manager.disknav` / `org.deepin.panshi.disknav`），
  且 `registerObject` 需显式传入接口名，否则接口名默认为类名导致调用失败。

### 4.4 主题体系（UI 重构阶段 0–4 后）

**核心原则：退掉自绘，把视觉控制权交还 DTK。** 应用层只表达「结构与语义」。

- **颜色职责全部归 `DPalette`**：所有颜色经
  `DGuiApplicationHelper::applicationPalette()` 或控件自身 `palette()` 运行时取值，
  在 `applicationPaletteChanged` / `themeTypeChanged` 时自动跟随，**不存在需要手动重刷的色板**。
- **语义收敛**：颜色意图统一经 `PanshiUi::Semantic`（Muted / Normal / Accent / Success /
  Warning / Danger）表达，由 `PanshiUi::semanticColor()` / `applySemantic()` / `softFill()` 派生。
  **禁止 hex 色值**，**禁止 QSS 属性选择器**（`#id[stat=...]{color:...}`）染色。
  原 17 个 hex 语义色常量已随阶段 1 删除。
- **`style.h` 只管布局**：仅保留承担布局职责的 QSS（间距/圆角/尺寸约束），
  其中不含任何颜色规则。原 `#panshiSwitchStatus` / `#panshiLinkBtn` / `#panshiTag*` /
  `#panshiWarnBox` / `#panshiTipBar` / `#panshiStatValue[stat]` 已全部移除。
- **图标**：全部走 `DIconTheme::findQIcon()`（缺失回落到 `QStyle` 标准图标）。

### 5.3 统计口径说明

- **容量/已用**：`df -B1 /`（根分区）；**目录归属**：`du`（跨所有挂载）。
- 由于磐石系统 /var、/home、/usr 等为独立挂载/overlay，**不能使用 `du -x`**
  （会漏掉独立挂载），改为显式排除伪文件系统：`--exclude=/proc --exclude=/sys

- `/ostree` 与 `/persistent`、`/sysroot` 存在同一仓库的多挂载视图，topLevel 合计
  可能与 df 已用不一致（重复计数），属磐石布局固有现象，不影响逐日 diff 定位增长。

## 6. 磁盘监控子系统（src/disk）

### 6.1 总体设计

```
systemd user timer（每 15 分钟）
        │ systemctl --user enable/disable（GUI 开关联动）
        ▼
panshi-manager --monitor  ──► DiskMonitor::runCycle（一轮后退出，崩溃自愈）
        │ df 采样 → 追加样本
        │ 对比最近完整日 → 异常? → du 顶层 → du 下钻定位元凶
        │ 每日基线：完整 du 保存 topLevel / drillCache
        ▼
~/.local/share/panshi-manager/disk-history/
        ├── index.json              # 轻量索引（KB 级，时间线快速渲染）
        ├── YYYY-MM-DD.json         # 当日完整记录（原子写）
        └── alert.json              # 告警列表（GUI 角标/横幅读取）
        ▲
GUI：DiskUsagePage（QFileSystemWatcher 监听目录变更 → 防抖刷新）
```

### 6.2 三层采样（性能关键）

| 层级 | 频率（默认） | 成本 | 作用 |
|---|---|---|---|
| 高频轮询 | 每 15 分钟 | 几乎为零（仅 `df`） | 感知总量突然上涨 |
| 事件触发定位 | 增长超阈值时按需 | 中 | 只对增长目录 `du` 下钻定位元凶 |
| 每日基线 | 每日 1 次 | 中 | 完整 `du`，供时间线/趋势/预测 |

- 所有 `du` 以 `nice -n 19` + `ionice -c3` 低优先级执行。
- **双重确认**：连续两次采样确认增长才触发定位/告警（过滤下载→删除的瞬时波动）。
- **root 自动降级**：自动扫描仅 `sudo -n`（不弹窗）；失败自动回退普通用户扫描，
  记录标记 `complete=false`（时间线灰色显示）；手动扫描才允许 pkexec 弹窗提权。

### 6.3 DiskScanner（scanner.{h,cpp}）

- `startTopLevelScan()`：`du -k --max-depth=1 --exclude=/proc --exclude=/sys
  --exclude=/dev --exclude=/run --exclude=/tmp /`，流式解析 `大小\t路径` 行。
- `drillInto(dir)`：`du -ak --max-depth=1 ... <dir>`（`-a` 含文件，`QFileInfo` 判目录）。
- `dfRoot()`：`df -B1 /` 解析总容量/已用。
- 信号：`progress(itemsDone, currentPath)` / `topLevelFinished(items, complete)` /
  `drillFinished(dir, items)` / `scanFinished(ok, error)`；`cancel()` 可中断。
- 关键坑（已修复）：`du -s` 与 `--max-depth` 冲突会直接警告无输出；`-x` 会漏掉
  独立挂载的 /var /home /usr。

### 6.4 DiskHistoryStore（history.{h,cpp}）

- **存储布局**：`index.json` + 每日期一个 JSON，文件原子写（QSaveFile tmp+rename），
  永不整体重写历史。
- **懒加载**：`requestRange(from,to)` 异步逐日读取（requestId 取消 + LRU 缓存 +
  `rangeProgress/rangeLoaded` 信号）；`loadIndex()` KB 级毫秒返回。
- **预算降级**（默认 512MB，可配 256/512/1024）：占用达预算时按阶梯自动处理——
  ① 裁剪非近期 samples → ② 裁剪非近期 drillCache → ③ 最旧记录合并为聚合摘要 → ④ 停止。
- **保留**：`pruneExpired(retentionDays)` 默认 400 天（90~730 可配）。
- **统计**：`computeRangeStats`（区间汇总/趋势起始日/容量预测 etaDays）、
  `detectSpikes`（按阈值找飙升日）、`topGrowthItems`（前后两日 topLevel 差值 + drillCache）。

### 6.5 DiskMonitor（monitor.{h,cpp}）

一轮 `runCycle()` 状态机：
1. 读配置；未启用 → 直接退出（timer 空转成本为零）。
2. `df` → 更新/新建当日记录，追加样本。
3. 取最近有 topLevel 的历史日做基准，计算增长。
4. 增长 ≥ 阈值 → 顶层 `du` → diff 定位最大增长目录 → 下钻 `du` 找到具体子项。
5. 冷却/排除目录/免打扰时段过滤后 → 发送 DDE 通知 + 写入 alert.json。
6. 若当日尚无完整基线 → 补一次全量 `du`（同时完成基线）。
7. `saveDayRecord`（内部执行保留/预算清理）→ 退出。

**告警判定**：`monitor.alertMode` 双模式——
- `baseline`（默认）：近 7 天正向日均增长 × `baselineMultiplier`（默认 3.0），
  且不小于 `minAlertMB`（512）；
- `fixed`：固定 `fixedThresholdMB`（1024）。

**通知**：`org.freedesktop.Notifications`，含 `x-deepin-action-view` hint
`panshi-manager,--show-disk,<date>` 实现"查看详情"。

### 6.6 MonitorConfig（monitorconfig.{h,cpp}）

- 以 DConfig（`org.deepin.panshi-manager`）为主；**开发机无 schema 时自动回退
  QSettings**（`deepin/panshi-manager` → `~/.config/deepin/panshi-manager.conf`）。
- ⚠ 关键坑（已修复）：DConfig 键用点号（`monitor.enabled`），QSettings 的 INI
  层级用斜杠（`monitor/enabled`），回退读写必须做 `.`→`/` 转换。
- GUI 设置页经 `setRawValue(key, value)` 统一写配置。

### 6.8 UsageChart（widgets/usagechart.{h,cpp}）

- 跨度 ≤180 天：柱状图（飙升日 danger 色、选中白色描边+顶部三角、点线趋势）；

### 6.9 DiskUsagePage（pages/diskusagepage.{h,cpp}）

六张卡：① 概览（df 进度条/监控状态/最近告警横幅）② 时间线（预设 7/30/90/180/365

## 9. 翻译（i18n）

### 9.1 机制

- **源语言 = 中文**：代码中所有用户可见文案已用 `tr()` 包裹，源串即中文。
- **装载**：`DApplication::loadTranslator()`（`src/main.cpp`）按
  `applicationName`（`panshi-manager`）在标准翻译目录中查找并装载 `.qm`。
- **生成与安装**：`CMakeLists.txt` 用 `qt_add_translations(panshi-manager TS_FILES …)`
  在构建时自动 `lrelease` 生成 `.qm`，**再由 `install(FILES …)` 显式安装**
  到 `share/panshi-manager/translations/`。
  ⚠️ `find_package(Qt6 … COMPONENTS … LinguistTools)` **不可省** ——
  缺该组件时 `qt_add_translations` 未定义，configure 阶段报
  `Unknown CMake command`（实测于 Qt 6.8.0：该命令仍在 `Qt6LinguistTools` 包内，
  **不随「Qt 6.7 起并入 Core」而变**）。
- **`.ts` 源文件**：`translations/panshi-manager_{zh_CN,en_US}.ts`
  （`zh_CN` 为恒等翻译，`en_US` 为真实译文）。

> ⚠️ **三条硬约束**（违反会「静默不翻译」，不报任何错）：
> 1. `.qm` 的 **basename 必须等于 `applicationName`**（`panshi-manager`）；
> 2. `loadTranslator()` 必须在**创建任何可翻译对象之前**调用 —— 包括
>    `setProductName` / `setApplicationDisplayName` / `setApplicationDescription`
>    以及所有窗口、控件；
> 3. **`.qm` 必须真正被安装到文件系统**（见下方「打包陷阱」）。

### 9.1a 打包陷阱：`RESOURCE_PREFIX` 不能替代 install 规则

**这是本项目最隐蔽的一个缺陷**（2026-10-03 B3 系统级安装时才发现）：

| 事实 | 后果 |
|---|---|
| `qt_add_translations(... RESOURCE_PREFIX "/i18n")` 只把 `.qm` 编进 **Qt 内嵌资源**（`:/i18n/`） | 内嵌资源**体积翻倍**，但没人读它 |
| **`DApplication::loadTranslator()` 只搜文件系统，不读 Qt 资源** | 内嵌的译文永远不会被加载 |
| `qt_add_translations()` **不生成 install 规则** | 干净系统上安装版**没有任何 `.qm`** |

后果是：开发期一切正常（因为手工 `cp` 到 `~/.local/share/…/translations/`
掩盖了缺失），**打包后在干净机器上英文界面静默回落中文** ——
且没有任何报错或告警可循。

**正确写法**（`CMakeLists.txt` 现状）：

```cmake
qt_add_translations(panshi-manager
    TS_FILES ${PANSHI_TS_FILES}
    LUPDATE_OPTIONS -no-obsolete
    QM_FILES_OUTPUT_VARIABLE PANSHI_QM_FILES   # ← 取出生成的 .qm
)
# 不使用 RESOURCE_PREFIX：Qt6.8 中它与 QM_FILES_OUTPUT_VARIABLE 互斥，
# 且 DTK loadTranslator() 不读内嵌资源
install(FILES ${PANSHI_QM_FILES}
        DESTINATION share/panshi-manager/translations)
```

`share/panshi-manager/translations/` = `GenericDataLocation/<appName>/translations`，
在 `XDG_DATA_DIRS` 内，与 `install.sh` 用户级 `~/.local/share/…` 分支同构。

> **通用教训**：验收「翻译生效」时若只在开发目录跑，会被手工同步掩盖。
> **必须在干净环境做一次真正的系统级安装再验**（B3 走的就是这条）。

### 9.1a-bis 打包陷阱：`.desktop` 的 `Exec` 不能写死绝对路径

深in's 磐石系统 `/usr` 是只读 overlay，**实际安装前缀是 `/usr/local`**
（独立 rw 的 ext4，且在 `PATH` / `XDG_DATA_DIRS` 内）。
`.desktop` 若写死 `Exec=/usr/bin/panshi-manager`，装到 `/usr/local` 后
**开始菜单点击会找不到程序**。

**正确写法**（`CMakeLists.txt` 现状）：源文件用占位符，
`configure_file` 按实际前缀生成：

```desktop
Exec=@PANSHI_BINDIR@/panshi-manager
```

```cmake
include(GNUInstallDirs)
set(PANSHI_BINDIR "${CMAKE_INSTALL_FULL_BINDIR}")   # 绝对路径
configure_file(org.deepin.panshi-manager.desktop
               ${CMAKE_CURRENT_BINARY_DIR}/org.deepin.panshi-manager.desktop @ONLY)
install(FILES ${CMAKE_CURRENT_BINARY_DIR}/org.deepin.panshi-manager.desktop
        DESTINATION share/applications)
```

`install.sh` 的用户级分支同步用 `sed` 替换该占位符。

> 两条形态都要能工作：**开发机（只读 `/usr` → 装 `/usr`）**与
> **打包镜像（`/usr` 可写 → 装 `/usr/local`）**。写死任一绝对路径都会让
> 另一种形态的开始菜单失效。

> ⚠️ **良性告警**：`Can't acquire config manager` —— DSG 库硬编码只认只读的
> `/usr/share/dsg`，`DSG_DATA_DIRS` 在这版 DTK 实测**不生效**。
> 磁盘监控配置有 `QSettings` 兜底（GUI 实测正常读写），非回归；
> 打包镜像（`/usr` 可写）时该告警自然消失。

### 9.1b 验证翻译是否生效（两个会导致假阴性的坑）

复测实测确认，以下两点都会让「翻译看起来没生效」而实际是**环境问题**：

| 坑 | 现象 | 正解 |
|---|---|---|
| **`LANGUAGE` 优先级** | deepin 会话进程默认继承 `LANGUAGE=zh_CN`；gettext 优先级下它**压过** `LANG`/`LC_ALL`，只设后两者无效 | 三个都设：`LANGUAGE=en_US.UTF-8 LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` |
| **`.qm` 查找路径** | `build/` **根目录不在** `loadTranslator()` 的查找列表；`.qm` 放那里等于没放 | 装到 `~/.local/share/panshi-manager/translations/`（或 `cmake --install`），再启动 |

```bash
mkdir -p ~/.local/share/panshi-manager/translations
cp build/*.qm ~/.local/share/panshi-manager/translations/
LANGUAGE=en_US.UTF-8 LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 \
  QT_QPA_PLATFORMTHEME=deepin ./build/panshi-manager
```

**告警行为不对称**（排障时别指望日志）：`zh_CN`（源语言）缺 `.qm` 会告警
`can not find qm files for locales QList("zh_CN")`，而 `en_US`（目标语言）
缺 `.qm` **完全静默**。

### 9.2 维护流程

需 `qt6-tools-dev-tools`（提供 `lupdate` / `lrelease`），在开发机执行：

```bash
sudo apt install -y qt6-tools-dev-tools

# ① 从源码提取/更新 .ts（保留已有译文；新增条目留空待译；消失的条目标 obsolete）
lupdate src/ -ts translations/panshi-manager_zh_CN.ts \
                translations/panshi-manager_en_US.ts

# ② 编辑译文（Qt Linguist 或直接改 .ts）
linguist translations/panshi-manager_en_US.ts

# ③ 正常构建即可 —— CMake 会自动 lrelease 生成 .qm 并安装
cmake --build build -j"$(nproc)"
```

`qt_add_translations()` 还提供 `update_translations` 目标（等价于 ①）：

```bash
cmake --build build --target update_translations
```

**未译条目在运行时回落到源串（中文），不会显示空白** —— 因此机制可先合入、
译文增量补充。

> ⚠️ **手写 `.ts` 的 XML 注释约束**：XML 注释 `--` 内部不得再出现 `--`。
> 用 `-----` 作分隔线会让 `lrelease` 报 `Parse error`、**`.qm` 根本生成不出来**。
> 手写 `.ts` 的注释分隔线一律用 `=`。`lupdate` 生成的文件不会踩此坑。


### 9.3 桌面文件

`org.deepin.panshi-manager.desktop` 的 `Name` / `Comment` 已带
`[en_US]` 变体（启动器按 locale 取用），与 `.ts` 是两套独立机制，改文案时需同步。

### 10.2 注意事项

- 测试环境无免密 sudo 时，监控自动降级为普通用户扫描（`complete=false`，时间线灰色）；
  真实 Deepin 环境配置 sudo 后为完整扫描。
- **提权链是两级回退**（`backend.cpp::runProcess`）：
  `sudo -n` 免密 → 失败且 **stderr 含 `password`** 时回退 `pkexec`（阻塞等 polkit 授权框）。
  → 推论：并非「无免密即所有写操作必然失败」。凡 sudo 失败原因含 `password` 的操作
  （如策略页「保存系统参数」实测会弹真授权框）**在真机上是可以通过 GUI 授权走通成功分支的**；
  只是自动化脚本无法输入密码，故自动化验证仍不可达。
  反之，sudo 失败原因**不含** `password` 的操作（如用户不在 sudoers 组）不会触发回退，直接失败。
- systemd 单元未 `cmake --install` 前，GUI 开关会报 "Unit file does not exist"（预期）。
- 验证英文翻译时必须显式设 `LANGUAGE`（deepin 会话默认继承 `LANGUAGE=zh_CN`，
  优先级高于 `LANG`/`LC_ALL`），且 `.qm` 需在 `loadTranslator()` 的查找路径内
  （`build/` 根目录**不在**）—— 详见 §9.1b。
- ASAN 构建曾暴露空指针动画 bug（已修复）；后续偶发 `DEADLYSIGNAL` 出现在未插桩的
  DTK/Qt 库 D-Bus 拆除阶段，属 ASAN 环境伪影，正式版（Release）稳定。
