## 一、3-4 反馈修复：横幅语义不再依赖颜色

### 1.1 先纠正一个证据链问题

3-4 反馈的推断是「折叠区红色警告文字 + 确认框红色按钮都正常 → 说明 `TextLively` 文字色没坏，灰的只有 banner 的 softFill 混合底色」。

代码核对后，这个推断不成立：

| 你观察到的红色 | 实际取色路径 | 是否经过 `TextLively` |
|---|---|---|
| 折叠区警告文字（`protectionpage.cpp#L94`） | `Semantic::Warning` → `DPalette::TextWarning` | ❌ 不经过 |
| 确认框红色按钮 | DTK `DDialog::ButtonWarning` 内部配色 | ❌ 不经过 |
| **失败的提示条底色** | `Semantic::Danger` → **`DPalette::TextLively`** | ✅ 经过 |

也就是说，两处红色**都没有碰过 `TextLively`**，无法作为它正常的证据。而两轮独立观测（3-3 采样 + 3-4 横幅）都指向 `TextLively` 在本环境解析为灰色。结论：**`softFill` 的混合逻辑没有问题，是输入色本身是灰的**。

### 1.2 处置：不改映射，改为"不依赖颜色"

`TextLively` 是 DTK 的「活动色文字」角色，不是危险色角色；但**在正常主题下的真实取值无法在本机验证**（本轮环境为 linglong 缓存的 DTK 6.7.46，非系统 DTK）。基于降级环境的观测去改全局语义映射，风险大于收益——所以映射**保持不动**，改为让提示条不依赖它：

| 通道 | 改动前 | 改动后 |
|---|---|---|
| 语义载体 | 仅"柔和底 + 彩色小字" | **图标（新增）+ 柔和底**；正文改中性色 |
| 图标 | 无 | `dialog-ok` / `dialog-information` / `dialog-warning` / `dialog-error`，缺失回落 `SP_DialogApplyButton` / `SP_MessageBoxWarning` / `SP_MessageBoxCritical` |
| 柔和底 alpha | 15%（`Alpha::SoftFill`） | **20%（新增 `Alpha::BannerFill`）**——整条面积大，15% 太虚 |
| 正文色 | 语义色（小字 + 语义色） | `Semantic::Normal` |

理由写进了 `components.h` 的类注释：彩色小字在浅色柔和底上对比度不足（WCAG AA 需 4.5:1），且主题色一旦异常，正文会跟着一起失去可读性。**图标是颜色之外的第二条信息通道**——这同时满足 WCAG 1.4.1（不得以颜色作为唯一信息载体）。

`Danger` 与 `Warning` 的区分因此落在三处：图标（`dialog-error` vs `dialog-warning`）、确认按钮类型、文案。

### 1.3 一处连带的克制决定

考虑过把 `Danger` 回退成 `TextWarning`（方案 §2.3 原文写法）。核对了 `usagechart.cpp#L350` 后发现**图表用的是原始 `DPalette` 角色、不经过 `semanticColor`**：

- 折线"异常增长"点 = `TextLively`；"选中日"点 = `TextWarning`
- 图例经 `Ui::legendDot(Semantic::…)` → `semanticColor`

一旦把 `Danger` 也映射到 `TextWarning`，"异常增长"与"选中日"会**撞色**，且图例与折线不再一致。故本轮不动映射，仅把结论列入待验清单（见 §四）。

## 三、阶段 3-5：总览页重写

文件：`src/pages/overviewpage.h`、`src/pages/overviewpage.cpp`（均全量重写）

### 3.1 结构调整

| 区块 | 旧 | 新 |
|---|---|---|
| 页头 | `Ui::pageHeader` | 不变（保持阶段 2 的页头唯一化成果） |
| 功能总开关 | `Ui::card` + `cardLayout` | **`PanshiSection`**「磐石功能」 |
| 状态卡 | 自绘 `statCard()` + `panshiStatValue` + `stat` 属性 + QSS 属性选择器染色，**固定 4 列 `QGridLayout`** | **4 × `PanshiStateCard`**，`QHBoxLayout` 等宽自适应（修"状态卡恒 4 列不响应"） |
| 系统信息 | `Ui::card` + 2×2 `QGridLayout` + 裸 `DLabel` | **`PanshiSection`** + 2×2 网格，每格一个 **`PanshiRow`**（左字段名 / 右值） |
| 存储空间 | 同上 | 同上 |
| 快速操作 | `Ui::card` + 3 按钮 | **`PanshiSection`** + 3 按钮（`gotoPage` 目标沿用阶段 1-a 修正值） |

### 3.2 状态色去装饰化（修问题清单中的"状态色退化成装饰色"）

旧实现 4 张卡是蓝 / 橙 / 绿 / 紫四色，**颜色不表示任何状态**。新映射：

| 卡片 | 值 | 值/徽章语义 |
|---|---|---|
| 磐石保护 | 开启 / 关闭 | `Success` / `Danger` |
| 系统可写层 | 已开启 / 已关闭 | `Warning` / `Success` |
| 备份快照 | `N 个 · 12.3 GB` | `Normal`（无状态语义 → 不显示徽章） |
| 系统盘剩余 | `123.4 GB` | `Normal`（同上） |

即：颜色重新只表达"正常 / 注意 / 危险"，不承担"区分第几张卡"的装饰职责。

### 3.3 加载态：修掉"连闪两次灰屏"

根因：本页分两步取数（快速状态 + 慢速存储统计），每次 `runAsync` 各盖一层全页遮罩 → 切到总览页连闪两次。

新策略（方案 §4.5 三档加载）：

| 时机 | 表现 |
|---|---|
| 首次进入 | `setMaskLoadingEnabled(false)` + **L1 骨架屏**（`PanshiSkeleton`，3 行脉冲）占位在状态卡位置，卡片隐藏 |
| 第二步取数（慢） | 卡片已入场，值显示「计算中… / 统计中…」；**L2 局部加载**（页头下方一行 spinner + 文案） |
| 再次切回 | **骨架屏不再出现**，旧值保留在屏，仅局部 spinner —— 无闪屏 |

`m_firstLoad` 标记承担"首次 / 后续"分流；`reduceMotionRequested()` 开启时骨架屏不做脉冲。

## 四、需编译侧验证（6 点）

1. **提示条三条链路**：保护页设置失败 → 灰色底上有 `dialog-error` 图标 + 中性可读正文 + 常驻可关；策略页失败态同理；更新页成功态图标为 `dialog-ok`
2. **提示条底色 alpha 提升**后对比度是否合适（20% vs 原 15%）——亮 / 暗主题各看一眼
3. **总览页首屏**：切到总览 → 骨架屏一次 → 状态卡入场，**全程无整页灰遮罩**；再切走切回 → 无骨架屏、旧值保留
4. **8 个信息行**：`PanshiRow` 在 2×2 网格中说明行高不空占（`m_desc` 已默认隐藏），值右对齐不被挤压
5. **状态卡等宽自适应**：拖窄窗口 4 卡随之压缩，不再恒 4 列
6. **状态色**：可写层开启时"系统可写层"卡应为注意色、其余卡为中性/正常色；4 卡不再出现 4 种装饰色
