## 一、本页的特殊性

磁盘空间页是 3 系列里唯一「有自己独立设计文档 + 后台监控服务」的页面，
因此本轮**只动 UI 层，不动任何数据/服务逻辑**：

| 保留不动（数据与行为） | 改动（仅呈现层） |
|---|---|
| 时间线按范围懒加载（`requestRange` / `rangeProgress` / `rangeLoaded`） | 卡片容器 → `PanshiPanel` / `PanshiSection` |
| `QFileSystemWatcher` 监听数据文件 → 400ms 防抖刷新 | 服务状态徽章 → `PanshiBadge` |
| pkexec 提权扫描 + 实时进度 | 告警 / 容量预测 → `PanshiInlineBanner` |
| 排行下钻 / 帧栈返回 / 打开位置 | 区间汇总 4 数值卡 → `PanshiStateCard` |
| 设置项读写（`MonitorConfig` / `applyConfigToStore`） | 表格列宽策略 + `ElidedLabel` + 窄窗兜底 |
| 启动检查流程（雷达面板 + 步骤耗时） | 设置窗口分组 → `PanshiSection` + `PanshiRow` |

## 二、改动清单

### 2.1 卡片层（① 概览 / ② 时间线）

| 原实现 | 现实现 |
|---|---|
| `Ui::card()`（`DFrame#panshiCard` + QSS 描边） | `PanshiPanel::Surface`（自绘圆角底，不描边） |
| `Ui::cardTitle()` 手工拼标题行 | `PanshiSection(title, desc)` |
| 「立即扫描」混在图例工具栏右侧 | 提到**组标题行右侧**（`addHeaderWidget`，与策略页「保存」同范式） |

### 2.2 语义承载方式的统一（本轮重点）

原实现大量使用「`objectName` 切 QSS / `setProperty("stat")` + 属性选择器」表达语义，
本轮全部收敛到组件层：

| 原实现 | 现实现 | 语义 |
|---|---|---|
| `DLabel#panshiTagPrimary/Success/Danger` | `PanshiBadge` + `setSemantic()` | 监控服务状态（Muted/Success/Danger） |
| `DLabel#panshiWarnBox` | `PanshiInlineBanner(Danger)` | 磁盘增长告警 |
| `QFrame#panshiTipBar` + `#panshiTipText` | `PanshiInlineBanner(Warning/Accent)` | 容量预测 |
| `DLabel#panshiStatValue` + `stat="blue/orange/green"` | `PanshiStateCard::setValue(v, semantic)` | 区间汇总 4 数值 |

**顺带修正的两处语义问题**：

1. **告警文案去掉「⚠」字符**：语义由 Banner 的图标承载（WCAG 1.4.1 —— 不依赖字符/颜色传递信息）。
2. **时间线范围提示（`m_timelineHint`）改中性色**：原用 `#panshiTipText` 会给它上强调色，
   但它只是「当前显示：系统盘占用变化」这类说明文字，语义过重；改用 `Ui::rowDesc`（Muted）。

### 2.3 配色语义的重新归类

原实现用「blue / orange / green」这类**装饰性**色名给数值卡上色（颜色不表示状态）。
本轮改为按语义归类：

| 卡 | 原 stat | 现语义 | 理由 |
|---|---|---|---|
| 净增长 / 日均增长 / 趋势起始日 | blue | `Accent` | 中性数值，跟随主题强调色 |
| 最大单日 | orange | `Warning` | 是「需留意的峰值」，语义上确实是 Warning |

### 2.4 概览使用率条：从 QSS 属性切色改为 palette 角色

原实现：`m_usageBar` 设 `level="warn"/"danger"` 属性，由 QSS
`#panshiUsageBar[level="warn"]::chunk` 切色。

**问题**：`unpolish/polish` 强制重算，且颜色只落在进度条 chunk 上——
<75% / 75~90% / ≥90% 三档的差别只有一条 14px 高的色块，辨识度低。

**现实现**：语义移到**大数值文字色**上（`setForegroundRole` 传 DPalette 角色）：

| 使用率 | 文字色 |
|---|---|
| < 75% | `TextTitle`（正常） |
| 75% ~ 90% | `TextWarning`（留意） |
| ≥ 90% | `TextLively`（危险） |

进度条本体保留 DTK 原生外观。**颜色不是唯一载体**——百分比数字本身就在条上显示。

> 类型坑（已记录以免重蹈）：`TextTitle/TextWarning/TextLively` 是 **`DPalette::ColorType`** 的值，
> 不是 `QPalette::ColorRole`。**不存在 `DPalette::ColorRole` 这个类型**，不要声明它。
> 写法与 `common.h` / `snapshotsPage` 一致：直接 `setForegroundRole(DPalette::TextTitle)`。

### 2.5 表格：统一列宽策略（与 3-6 同方案）

`makeTable()` 原用 `ResizeToContents`——**长路径会把表撑爆**（本页路径动辄
`/home/xxx/.../very/long/path`），且与快照/部署页的列宽手感不一致。

现实现：

```cpp
// 列宽全部 Interactive；第 0 列（名称/路径）Stretch 吸收剩余
// 其余列固定：大小 120 + [占比 90] + 操作 72
// 名称列用 Ui::ElidedLabel（中部省略 + tooltip 兜底完整路径）
// 窄窗兜底：横向 SizePolicy=Ignored + 自身横向滚动条 AsNeeded
```

| 表 | 列 | 固定合计 | 最小总宽 |
|---|---|---|---|
| 增长详情 | 名称弹性 + 大小 120 + 操作 72 | 192 | 264px |
| 占用排行 | 名称弹性 + 大小 120 + 占比 90 + 操作 72 | 282 | 354px |

远小于默认视口 → 默认态不出滚动条；窄窗下由表格内部滚动条承担（同 3-6 方案）。

### 2.6 设置窗口：分组组件化

原实现：「`QFrame` 分隔线（`#panshiSep`）+ `#panshiGroupTitle` + 手拼 `QHBoxLayout` 行」。
现实现：每组一个 `PanshiSection`，每行一个 `PanshiRow`（左标题+说明 / 右控件），
与策略页等设置页同构。窗口从 540×560 调整为 560×580（容纳 Section 的内边距）。

### 5.1 问题 A【高】设置窗口数值控件被挤压，当前值不可读

**现象**：固定阈值 / 基线倍数 / 告警冷却三个 spinbox 的数值区被压到 0~28 逻辑 px
（显示「…」或 2px 竖缝）；告警模式下拉「智能基线」截为「智能…」。

**根因（组件级，非本页独有）**：
`PanshiRow` 构造函数此前是

```cpp
lay->addLayout(texts, 1);        // 文本列承担拉伸
lay->addLayout(m_controls);      // ← 控件列无任何约束
```

空间不足时 Qt 把各子项压向各自 `minimumSizeHint`：
`DSpinBox` / `DComboBox` 的 `minimumSizeHint` 极小（几十像素）→ 先塌；
而左侧说明 `wordWrap=true` 时 `sizeHint` 巨大，反而"抢"宽度。
**影响面是所有用 `PanshiRow` 的页面**（策略 / 保护 / 总览 / 磁盘），不止本页。

**修法（修在组件层，不在调用点打补丁）**：

1. `tokens.h` 新增 `Size::RowControlMinWidth = 200`
   （够放下「告警冷却 [数值] 小时」这类带后缀控件 + 间距）；
2. `PanshiRow` 把控件列包进 `m_controlsHost`（`QWidget`），设
   `setMinimumWidth(Size::RowControlMinWidth)`
   —— **布局只在 widget 上认 `minimumWidth`，layout 上设无效**；
3. 磁盘页调用点再加显式下限 `setMinimumWidth(140)` 兜底
   （`m_alertModeBox` / `m_fixedThresholdSpin` / `m_multiplierSpin` / `m_cooldownSpin`；
   `m_retentionSpin` / `m_budgetBox` 各一条）。

> 与表格列宽同一课：**显式最小宽度是布局挤压下唯一可靠的防线**。
> 本轮在三处印证：表格列（3-6）→ `PanshiRow` 控件区 → 数值控件。

### 5.2 问题 B【低】「加载中 N/N …」标签永不消失

**现象**：`onRangeLoaded` 完成后状态标签仍停在「加载中 N/N …」，4 次观测均复现。

**根因**：`onRangeProgress` 写 `m_loadStatus`，但 `onRangeLoaded` 收尾时未清。

**修法**：改为写终态文案（而非延时隐藏——无计时器、无状态泄漏）：

```cpp
m_loadStatus->setText(records.isEmpty()
                          ? tr("该范围内暂无监控数据")
                          : tr("已加载 %1 天记录").arg(records.size()));
```

### 5.3 观察点：无数据时「最大单日」也上 Warning 色

用户提出「无数据时 dash 也上 Warning 色，要不要降中性色由你斟酌」。

**已采纳**：`updateSummary()` 改为有值才 `Warning`，空格子用 `Muted`
——空格子不该带"需留意"的语义。

### 5.4 设置窗口高度（用户问「是否加高由你定」）

**结论：暂不加高**。理由：4 组一次全见会与其它设置页的密度手感不一致，
且该窗口本身已支持滚动（DTK 覆盖式滚动条，滚动可达）。
