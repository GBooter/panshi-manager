# UI 重构进度 — 阶段 3-3：策略与设置页

> 前置：阶段 0/1/2、3-1（关于页）、3-2（系统更新页）均已验收通过。

## 一、改动内容

### policypage.h
- 新增 `PanshiUi::PanshiInlineBanner *m_banner`、`PanshiUi::PanshiLocalLoading *m_busy`；
- 引入 `ui/components.h`（与 3-2 更新页保持一致的头文件范式）；
- 控件成员（2 个 DSwitchButton / 3 个 DSpinBox / 1 个 DComboBox）与数据加载逻辑不变。

### policypage.cpp 全量重写
| 维度 | 旧 | 新 |
|---|---|---|
| 表单 | 手拼 `QHBoxLayout`（rowLabel + stretch + 控件 + rowDesc） | `PanshiRow`（左标题+说明 / 右控件），6 行统一 |
| 卡片 | `Ui::card()` + `Ui::cardTitle()` | `PanshiSection` ×2（备份保留策略 / 磐石系统参数） |
| 保存按钮 | 卡片底部右对齐的独立行 | 上移为「磐石系统参数」分组的**组级操作**（标题行右侧，`addHeaderWidget`） |
| 反馈 | `Ui::infoDialog` / `Ui::errorDialog` 模态弹窗 | `PanshiInlineBanner`：保存成功 3s 自动消失，失败常驻可关 |
| 加载 | 整页遮罩（读取配置 / 保存时） | `PanshiLocalLoading` + `setMaskLoadingEnabled(false)` |

**行为保持不变**：
- 应用侧配置（auto_prune / max_snapshots / rb_auto_clean）仍即时写入 `~/.config/panshi-manager/config.json`；
- **所有 `setValue/setCurrentIndex` 均在 `connect` 之前执行**——避免加载配置时触发 valueChanged 回写（原实现即是此顺序，重写时保留）；
- 系统参数保存路径、`getCtlConfig/getRollbackState/setCtlConfig` 调用与 onLoaded 解析逻辑逐行等价。

## 二、需编译侧验证（4 点）

1. **行式表单渲染**：6 行均为「左标题+说明 / 右控件」，说明文字换行正常，控件右对齐不挤压。
2. **保存反馈**：点「保存系统参数」→ 成功出现绿色 Banner「系统参数已保存」并 3s 自动消失；失败（无 sudo 权限时本机常见）→ 危险色常驻、右上角可关闭。
3. **局部加载**：进入页面「正在读取配置...」spinner 出现在页头下方，**不出现整页灰遮罩**；读完后消失。
4. **无误写配置**：进入/切换页面不应改动 `config.json` 时间戳（验证 setValue-before-connect 生效）。
