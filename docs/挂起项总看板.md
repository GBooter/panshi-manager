**一键脚本**：`verify-unlocked.sh`（默认干跑，`--go` 才实际执行）

> 若账号不在 sudoers 组，失败原因是「用户不在 sudoers 组」→ 不触发回退。

### V-23 换色要点（2026-10-03）

`DPalette::TextLively` 在 **DTK 默认主题下就是中性黑**（非降级环境的灰），
用它表达「危险」→ 磁盘页 ≥90% 的「已用」与百分比渲染成普通正文黑、
**危险语义完全失效，且外观看不出 bug**。根因是**角色语义错配**
（DTK 里 `TextLively` = 「活跃式文本（不受活跃色影响）」）。

经用户决策：**复用 `TextWarning` + 仅改 Danger 语义链路**（不引入硬编码 hex）。
已改 3 处 + 注释：`semanticColor()` / `applySemantic()`（**两份映射必须同步**）/
`diskusagepage.cpp` 的 `usageRole`。

**已知代价**：75~90% 与 ≥90% **视觉不再区分**，两档语义改由文案与图标承载
（`bannerIconName()` 已按语义返回 `dialog-warning`/`dialog-error`，形状不同，
WCAG 1.4.1 成立）。日后要恢复区分应引入明确的危险色角色，
**不要回头用 `TextLively`**。

> **通则**：本项目已两次犯「文档/命名 ≠ 既成事实」——
> V-16（以为继承来的控件会画内嵌文字）、V-23（以为 `TextLively` 是警示色）。

### B3 系统级安装实测要点（2026-10-03）

- 磐石 **`/usr` 是 usr-overlay `ro` 挂载，不能装**；**`/usr/local` 是独立 ext4 `rw`**（`/var/usrlocal`），
  且在 PATH / XDG_DATA_DIRS 内、与编译期 DSG_DATA_DIR 一致 → 系统级安装落点是 **/usr/local**（默认 prefix，不要加 `--prefix /usr`）。
- 修复 1：`qt_add_translations(... RESOURCE_PREFIX)` 只把 .qm 编进 Qt 资源，**DTK `loadTranslator()` 只搜文件系统不读资源**，宏本身也不生成 install 规则 → 干净系统 en_US 回落中文。改为 `QM_FILES_OUTPUT_VARIABLE` + 显式 install 到 `share/panshi-manager/translations`（去 RESOURCE_PREFIX，Qt6.8 二者互斥）。
  **此前所有 i18n 测试能过，全靠手工 `cp` 到 `~/.local` 掩盖了它。**
- 修复 2：desktop `Exec=/usr/bin/...` 写死 → `configure_file` + `@PANSHI_BINDIR@`（GNUInstallDirs 注入实际前缀）；install.sh 用户级分支同步 sed。
- 遗留（平台约束，非缺陷）：DSG 库硬编码只认 `/usr/share/dsg`，只读 /usr 装不进，`DSG_DATA_DIRS` 在本机 DTK 6.7.47 实测不生效 → 启动有「Can't acquire config manager」告警；磁盘监控配置走代码内置 QSettings 兜底，GUI 功能实测正常。打包镜像（/usr 可写期）时该告警自然消失。

### V-30 暗色复核（唯一未结的视觉项）

**但 GUI 暗色在本机不可达**（环境限制，非缺陷）：

- DTK6 暗色走 **treeland Wayland personalization 协议**
  （库内 `treeland_personalization_appearance_context_v1`），
  **不读 gsettings `gtk-theme`** → 改 `gtk-theme` 只有 dock / GTK 应用变暗；
- `QT_QPA_PLATFORM=wayland` 启动 → **SIGABRT**。

→ **做法**：`./verify-runtime.sh --go theme` 走一遍，
控制中心**手动切暗色**后肉眼复核整体观感（配色值本身已不再依赖这一步，见下）。
（V-27/V-28/V-31 已在亮色下通过，故此项**不阻塞**当前结论。）

**2026-10-04 更新：暗色的配色值已可自动断言。** `panshi-colorprobe` 在进程内
`DGuiApplicationHelper::setPaletteType(Dark) + standardPalette(Dark)` 强制应用内暗色，
绕过「系统级暗色不可达」的限制。实测（与旧探针 `#e43f2e` 吻合）：

| 主题 | 底色 | 正常色 | 对比度 | 警示色 | 对比度 |
|---|---|---|---|---|---|
| Light | `#ffffff` | `#28272a` | 14.85 | `#ff5837` | 3.13（大数值 28px）/ 3.08（百分比 18px） |
| Dark | `#282828` | `#dbdddc` | 10.80 | `#e33e2d` | 3.51（大数值）/ 3.42（百分比） |

→ 大数值按 WCAG「大文本 3:1」达标；百分比标签 18px 属正文档，**3.08~3.42 < 4.5**，

## 六、本项目固有的环境限制（每次复测都要重读）

| 限制 | 影响 |
|---|---|
| **助手侧 `Bash`/`Grep` 长期 exit 251** | 无法编译/运行/扫描；所有验收结论只能靠 `Glob`+`Read` 通读得出，**必须标注「非命令断言」**并给出实机复跑命令 |
| 本机无免密 sudo | 应用内 root 操作依赖 pkexec 弹框；命令行直接用 `sudo` 需密码 |
| 助手无法输入密码 | polkit 授权框必须由**用户**在 GUI 里点（但可用 `xdotool key Escape` 自动取消以触发失败态） |
| **GUI 暗色不可达** | DTK6 暗色走 treeland Wayland personalization，不读 gsettings `gtk-theme`；`QT_QPA_PLATFORM=wayland` 启动 SIGABRT。暗色验证需**控制中心手动切** |
| `SUDO_ASKPASS` / `LD_PRELOAD` 注入无效 | 应用用 `sudo -n`（非交互，不调 askpass）；`LD_PRELOAD` 被 `sbox.so` 清洗。造阻塞只能用 **SIGSTOP** |
| `DSG_DATA_DIRS` 不生效 | 该版 DTK 硬编码只认只读 `/usr/share/dsg` → 启动有 `Can't acquire config manager` 告警（QSettings 兜底，非缺陷） |
| `QT_LOGGING_RULES` 屏蔽 `qInfo` | 调试用 `qWarning` |
| 破坏性操作（开可写层、还原、重启） | 助手不代为决策，必须用户手工执行并自行回滚 |
