> 前置：阶段 3-7 磁盘空间页复测通过（9 点 + 复测 3 点全过）。
> 本轮 = **修复阶段 3-7 复测时发现的总览页窄窗溢出问题**（先存问题，与本轮组件改动无关）。

---

## 一、问题

阶段 3-7 复测的影响面核查中，在**窄窗（920 逻辑宽）**下发现：

| 现象 | 说明 |
|---|---|
| 第 4 张统计卡「46.89 GB」被截成「46.89 G」 | 内容被裁 |
| 「磐石功能」行的开关被推出视口，**完全不可见** | 功能不可达（比截字更糟） |
| 默认窗宽下两者立即恢复正常 | 用户实测确认 |

### 定性：外层容器静态裁剪（不是"卡片内容溢出"）

```
不是「控件内容溢出」（改列宽/省略能解决）
而是「外层容器静态裁剪」—— 与 3-6 表格问题同一层
```

**因果链**：

```
4 张状态卡是 QHBoxLayout 等宽硬排（各 stretch=1）
  → 窄窗下每张卡被压到各自 minimumSizeHint（由最长文本行决定）
  → 4 卡最小宽合计 > 视口宽
  → 卡片行整体横向溢出
  → scrollContent 的宽度被最宽子项撑大
  → 外层 Ui::makeScrollArea 是 ScrollBarAlwaysOff
  → 超出部分被静默裁掉，且不给滚动条
  → 第 4 卡右半被裁；「磐石功能」行的开关位于更右侧 → 完全出视口
```

**关键推论**（解释了为什么两个看似无关的元素同时出问题）：
`scrollContent` 是所有行的共同父容器，其宽度 = 最宽子项宽度。卡片行溢出后
`scrollContent` 被撑宽，**于是所有行一起被外层裁剪**——「磐石功能」行本身没有
溢出（它的布局是 `[图标][文本 stretch][详情][开关]`，右侧项 stretch=0 不该被压），
但它被"连累"了。修复卡片行溢出后，开关问题**自动消失**，无需单独修 `PanshiSwitchRow`。

> 用户实测「默认窗宽下开关恢复可见」正好印证：默认宽度下卡片行不溢出，
> `scrollContent` 不被撑宽，故无裁剪。

## 二、修法

### 2.0 组件层先行：新增 `PanshiResponsiveCardRow`

`PanshiStateCard` 的 168 下限一旦生效，**所有用它的页面**窄窗下都会遇到同一个问题。
若只在总览页写一份折行逻辑，磁盘页（4 卡）与保护页（3 卡）就要各自复制一份 ——
按本项目既有惯例（`ElidedLabel` 从 about 页提升到 `common.h` 的先例），
**第三处复制之前就该收敛**。故本轮把它做成组件层能力：

```cpp
// components.h
class PanshiResponsiveCardRow : public QWidget
{
    explicit PanshiResponsiveCardRow(int maxCols = 4, QWidget *parent = nullptr);
    void addCard(QWidget *card);
    void setAvailableWidth(int w);     // 喂入可用宽度 → 自动算列数并重排
    int columnCount() const;
};
```

**设计取舍**：容器**不做事件监听**，由调用方在 resize 时喂宽度。
理由：组件层不该假设上层是 `QScrollArea` 还是普通容器，也不该替调用方决定
"可用宽度"的口径（视口宽度 / 页面宽度 / 减多少内边距）。监听与口径留在页面。

### 2.1 组件层：`PanshiStateCard` 加显式最小宽度

`tokens.h` 新增：

```cpp
constexpr int StateCardMinWidth = 168;
```

取 168 的依据：够放下「46.89 GB」这类 T2 大数值 + 卡片内边距（`Space::L` × 2 = 32）。

`components.cpp` 的 `PanshiStateCard` 构造函数补：

```cpp
setMinimumWidth(Size::StateCardMinWidth);
```

横向 SizePolicy 保持 `Expanding` —— 下限只作用于「空间不足时不许继续缩小」，
宽裕时卡片仍应撑满分配的格子。

> 这是「显式最小宽度是挤压下唯一可靠的防线」的**第四处印证**
> （表格列 320 → `PanshiRow` 控件区 200 → 数值控件 140 → 状态卡 168）。

### 2.2 页面层：三处页面统一改用该容器

| 页面 | 原实现 | 现实现 | 改动理由 |
|---|---|---|---|
| 总览页 | 4 卡固定 `QHBoxLayout` | `PanshiResponsiveCardRow(4)` | 本轮问题的直接来源 |
| 磁盘页（区间汇总） | 4 卡固定 `QGridLayout` | `PanshiResponsiveCardRow(4)` | **168 下限引入后同样会溢出**，属本轮必须一并处理 |
| 保护页 | 3 卡固定 `QHBoxLayout` | `PanshiResponsiveCardRow(3)` | 3 卡预算 528px < 窄窗 672px，**当前不会溢出**；统一走组件层是为避免将来增卡时重蹈覆辙 |

**可用宽度的口径**（各页自行决定）：

| 页面 | 口径 | 说明 |
|---|---|---|
| 总览页 | `m_scroll->viewport()->width() - Space::XL*2` | 最准确：竖向滚动条自动扣除 |
| 保护页 | 同上 | 同上 |
| 磁盘页 | `width() - 48 - 48` | 内容在三层容器内（页面→滚动区→标签页），用页面宽度减常量，卡片有 168 缓冲足够 |

**触发时机**：

* 总览页：`installEventFilter` 在 viewport 上 —— viewport 宽度即真实可用宽度，
  且窗口 resize / 滚动条隐现都会发 `Resize`。
* 保护页 / 磁盘页：`resizeEvent` override —— 页内无嵌套滚动区，页面宽度够用。

**自锁问题的规避**：三处都**不读 `m_statRow->width()`**。
卡片行自身宽度会被当前列数影响（列数错 → 行被挤压 → 读到的宽度偏小 → 算出更少列，
形成向下自锁）。以「视口/页面宽度」为输入，布局结果与布局输入解耦。

### 7.2 发现 A【高】残留溢出，源头不是卡片行

用户用探针钉死：`viewport=720, scrollContent=806, statRow minHint=528, cols=3`

* **RCR 完全无辜**：cols 算对、自身最小宽只有 528。
* `scrollContent` 卡在 **806** 不缩（页面宽 771 时也 806）→ 最小宽被某个兄弟顶到 806。
* **源头**：「系统信息 / 存储空间」两组 2 列 `PanshiRow` 网格 ——
  `RowControlMinWidth = 200` 的宿主下限 + value 标签 `wordWrap(false)`
  （`6.18.36-amd64-desktop-rolling` 这类不折行文本自然最小宽 ~218）
  → 每行 ~346，两列 + 间距 + 边距 ≈ **806**。
* 溢出区间：窗口逻辑宽 < 1006；920 时裁掉 86px，第 3 卡右缘与开关正在裁剪带里。

**修法（采用用户建议的两条全做）**：

| 层 | 改动 | 理由 |
|---|---|---|
| `PanshiRow::addControl(w, minW = -1)` | 下限改为**逐控件累积的最大值**；`-1` → 200（交互控件），`0` → 不设地板 | **语义区分**：交互控件被压塌即不可用，必须保底；纯文本退化是优雅的（省略/折行），不需要地板 |
| `makeInfoRow` 的 value | 改 `Ui::ElidedLabel` + `addControl(v, 0)` | 可省略 + 无地板，整页最小宽回落到卡片行的 528 |

**顺带修了 `ElidedLabel` 的一个既有隐含缺陷**（`common.h`）：
原先只覆盖 `paintEvent`，未覆盖 `minimumSizeHint()` / `sizeHint()` ——
自身仍按完整文本索要宽度。`QHeaderView` 列的宽度由我们显式设定，故表格场景
看不出问题；但在 `QHBoxLayout` 里（信息行的值）它会撑破行，把整页最小宽顶上去。
补上 `minimumSizeHint()`（返回 24px）+ 横向 `QSizePolicy::Ignored`。

### 7.3 发现 B【中】`resizeEvent` 系页面首次进入 cols 粘在 1 列

保护页首次点入时 3 卡竖排单列，但代码逻辑正确（672 ≥ 528 应得 3 列）。
判定实验：手动拖宽一次 → 立刻弹回 3 列，缩回 920 后保持。

**根因**：`QStackedLayout` 的隐藏页**不跟随窗口 resize**。首次 show 时
`page` 的 `resizeEvent` 采到的是尚未布局的 viewport（探针实测 ≈100px）
→ `setAvailableWidth(52)` → cols=1；而切页不再触发 `resizeEvent` → **sticky**。

> 总览页免疫，正因为它挂的是 **viewport eventFilter** —— 我原先注释里写的
> 「比 resizeEvent 准」这次被保护页反向验证了。

**修法：把宽度喂入提升为 `BasePage` 的能力**（而不是三页各写一份）

```cpp
// basepage.h
void registerResponsiveCardRow(PanshiUi::PanshiResponsiveCardRow *row,
                               QScrollArea *scrollArea, int hPadding);
// 基类同时监听：
//   · viewport 的 Resize 事件（窗口缩放 / 滚动条隐现）
//   · BasePage::showEvent（隐藏页首次显示 —— 发现 B 的坑）
```

三页（总览 / 保护 / 磁盘）改为调用 `registerResponsiveCardRow`，
各自的 `relayoutStatCards` / `resizeEvent` / `eventFilter` 全部删除。

**额外补的一处**：磁盘页汇总卡在**标签页内**（`m_tabs`），
非当前标签时其 widget 隐藏 —— 标签内 widget 的 show **不会冒泡成
`BasePage::showEvent`**，故另接 `DTabBar::currentChanged` 在切到汇总标签时补喂一次。

### 10.2 回归【高】：`ElidedLabel` 横向 `Ignored` 导致值被分到 0 宽

**现象**（首屏即现）：「系统信息 / 存储空间」8 行的**值全部不可见，只剩标签**。

**根因链**：

```
ElidedLabel 横向 QSizePolicy::Ignored
  → 布局分配中 sizeHint 记 0（Ignored 的语义就是"我的 sizeHint 请忽略"）
  → PanshiRow 左侧文本列 stretch=1 吸走全部富余宽度
  → 值标签实际分得 0 宽 → 什么都不画

此前从未暴露：值标签带 200 宿主地板（minimumWidth）在挡着
addControl(v, 0) 一去掉地板 → 这条路径立刻现形
```

**我的失误性质**：上一轮我刚确立「控件区最小宽度按内容性质分流」这条规则，
**只改了「地板」那一层，没同步改「退化机制」那一层**。
`Ignored` + `minimumSizeHint(24)` 的组合里：`minimumSizeHint` 负责下限（可收缩）✅，
但 `Ignored` 在否掉「按全文宽要空间」的同时，**把"我想要自然宽"这个正当诉求也一并否了**。

**正确拆分**：**下限交给 `minimumSizeHint`，上限交给 `sizeHint`**，
横向策略用 `Preferred` 让 `sizeHint` 参与分配。`Preferred` 下 `minimumSizeHint` 依然生效，
故收缩能力不丢。

**修法（`common.h`）**：

```cpp
// 横向 Preferred 而非 Ignored
setSizePolicy(QSizePolicy::Preferred, QSizePolicy::Preferred);
```

`sizeHint()`（文本自然宽）与 `minimumSizeHint()`（24）**都保留**。

> **用户对我一个错误前提的纠正**：我原先担心「`Preferred` 会撑破行」——
> 该结论只在**没有 `minimumSizeHint` 覆盖**时成立（旧缺陷是 min=全文宽）。
> 现在 min=24，可正常收缩。

## 十一、本阶段方法论沉淀（含二轮修正）

1. **「控件区最小宽度」要按内容性质分流**：交互控件（不可压塌，需保底）vs
   纯文本值（可优雅退化，不应设地板）。一刀切地板会把整页最小宽顶上去，
   反而触发外层静默裁剪。
   > **二轮补充**：分流必须**两层同时改** —— 「地板」（`minimumWidth`）与
   > 「退化机制」（SizePolicy）。只去地板不改 SizePolicy，会让控件在带 stretch
   > 的兄弟项旁被分到 0 宽。**下限交 `minimumSizeHint`、上限交 `sizeHint`，
   > 横向用 `Preferred`** 才是完整解。
2. **`QStackedWidget` 隐藏页的首次显示是独立路径**：`resizeEvent` 采不到真实尺寸，
   必须走 `showEvent` 或 viewport eventFilter；且**嵌套 stacked（标签页）的 show
   不再冒泡到页面级**，需另接切换信号。这是「外层静态裁剪」的第三种触发场景。
3. **「显式最小宽度是布局挤压下唯一可靠的防线」已扩至四处印证**：
   表格列 320 → `PanshiRow` 控件区 200 → 数值控件 140 → 状态卡 168。
4. **编辑已代修过的文件前必须先 `Read` 确认现状**（本轮 `relayout()` 重复声明即此因）。
