## 二、真正根因：冻结机制在「构造期」误冻结了内容区

### 2.1 症状与表象

用户报「侧边栏切页没反应、标签页没反应、软件里内容全都没法点击」。
上一轮把矛头指向 CSD（`DPlatformHandle::setEnabledNoTitlebarForWindow`），
A/B 实测却得出「点击可用（diff=33,281,800）」，于是交付了「CSD 关、拖拽不可用」
的二选一状态。**那个 33M 的 diff 是假阳性**：它是鼠标悬停在侧栏项上的
**hover 高亮**（约 288×71 像素区域），不是页面切换。

### 2.2 探针证据链（本轮完整还原）

1. **hover 有效、点击无效**：鼠标移动时侧栏项有 hover 高亮（delegate 按
   `State_MouseOver` 绘制），但点击后无任何反应 —— 连选中态都不变。
2. **事件到达控件**：在 `QListView` viewport 上装事件过滤器，PRESS/RELEASE
   都到了（坐标正确、index=3 命中「磁盘空间」），但 `pressed`/`clicked`
   信号一个都没发。
3. **控件已禁用**：PRESS 时打印状态 —— `view enabled= false
   viewportEnabled= false`。**整个内容区是禁用状态**，QListView 收到事件
   但按禁用控件处理（忽略），事件向上冒泡到 view 也不产生任何动作。
   标题栏（不在 centralWidget 内）不受影响，所以只有「内容区」点不动。
4. **谁禁用的**：给 `makeDialogNonBlockingWindowModal` 加日志，启动即打出：
   `freeze applied for dialog Dtk::Widget::DDialog title="" parent=DiskUsagePage`，
   且**没有对应的 restore 日志** —— 冻结发生了、恢复永远没来。

### 2.3 代码根因

`makeDialogNonBlockingWindowModal()`（src/ui/components.cpp）本来的设计：
对话框弹出时 `centralWidget->setEnabled(false)`（用户不能越过对话框操作页面），
对话框 Hide/destroyed 时恢复。问题出在**冻结时机是「调用时立即执行」**：

```cpp
// 旧实现（错误）：调用即冻结
PanshiUi::makeDialogNonBlockingWindowModal(m_settingsDlg);   // ← 构造期调用
content->setEnabled(false);   // ← 立即禁用整个内容区
```

而 `DiskUsagePage::buildSettingsDialog()`（diskusagepage.cpp）在**页面构造时**
就创建成员对话框 `m_settingsDlg` 并调用了这个函数。主窗口 `initContent()` 把
**所有页面一次性 `new` 出来**（QStackedWidget 全量构造），于是应用一启动，
磁盘空间页的设置对话框就被构造 → 冻结立即生效 → 该对话框**从不显示**（用户
没点开设置）→ Hide/destroyed 恢复路径永远不触发 → **内容区永久禁用**。

### 2.4 为什么上一轮没抓到

- 上一轮用「CSD 开关 A/B」测试，CSD 开时确实会吞点击（那个现象也真实存在），
  但 CSD 关时的「点击正常」判定被 **hover 高亮假阳性**污染：截图对比 diff=33M
  就下了「画面全变、点击正常」的结论，实际只是悬停高亮。
- 事件过滤器证据（CSD 开时「收到 PRESS 却不动作」）与本次「禁用控件收到
  PRESS 却不动作」在日志上几乎无法区分 —— 都表现为事件到达、无动作。

## 三、修复

### 3.1 冻结时机改为「对话框 Show 时」

`src/ui/components.cpp`：把「调用即冻结」改为事件守卫 `DialogFreezeGuard`，
**Show 才冻结、Hide 恢复、destroyed 兜底恢复**：

```cpp
QPointer<QWidget> guard(content);
auto freeze = [guard] { if (guard) guard->setEnabled(false); };
auto restore = [guard] { if (guard) guard->setEnabled(true); };
dialog->installEventFilter(new DialogFreezeGuard(freeze, restore, dialog));
QObject::connect(dialog, &QObject::destroyed, dialog, [guard] {
    if (guard) guard->setEnabled(true);
});
```

`DialogFreezeGuard::eventFilter`：`QEvent::Show → freeze()`，
`QEvent::Hide → restore()`。setEnabled 幂等，重复开/关安全。
对「构造期创建、用时才 show」的成员对话框（如 m_settingsDlg）从此安全；
对栈上创建后立即 exec() 的对话框（快照/倒计时/确认框）行为不变。

### 3.2 拖拽与点击兼得（上一轮的互斥结论被推翻）

上一轮认为「CSD 开=能拖但点不动 / CSD 关=能点但拖不动」不可兼得。实际上
**两个问题没有因果关系**，点击失效的真根因是 §2.3 的冻结 bug（与 CSD 无关）。

拖拽修复（src/mainwindow.cpp）：
- 废弃 CSD 方案（`DPlatformHandle::setEnabledNoTitlebarForWindow`），
  它确实会吞掉整窗点击，别再启用。
- 改用 `DTitlebar::mousePressed/mouseMoving` 信号（DTK6 库中**无条件导出**，
  nm 已验证，不受 `DTK_TITLE_DRAG_WINDOW` 宏影响）：
  - X11：按下时记录基准（光标位置 + 窗口位置），移动时
    `win->setPosition(基准 + 光标位移)` —— 手动跟随，确定性生效，
    快速甩动（单次跳跃）也稳定。
  - Wayland：走 `QWindow::startSystemMove()` 交给合成器。
- 事件路径完全正常，不吞任何点击。

实测：单次跳跃拖拽 3/3 成功；拖拽后点击依旧正常。

## 四、验证判据（避免再次踩假阳性）

- **切页判据必须对比「点击前（鼠标已移开）」与「点击后（鼠标已移开）」**，
  且 diff 要覆盖整个内容区（≈5.9e9 AE 级别）。hover 高亮只有 ≈3.3e7，
  恰好是上一轮被骗的量级 —— 看到 3e7 级别的 diff 先怀疑是不是 hover。
- 点击失效排查顺序：先看控件 `isEnabled()`（禁用控件会「收到事件但不动作」），
  再看是否有 dialog 的冻结未恢复（给 makeDialogNonBlockingWindowModal 加日志）。
- 本机自动化测试前先把 `小U同学`（0x480006f）等常驻大窗口最小化，
  否则它们盖在应用上会吃点击（与上一轮记录的「外来窗口」同源）。
