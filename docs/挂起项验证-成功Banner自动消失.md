# 挂起项验证手册 · 成功 Banner 自动消失

> 用途：验证 `PanshiInlineBanner` 的**成功类反馈 5s / 3s 自动消失**。
> 该项自阶段 4 起长期挂起，根因是「本机无免密 sudo → 写操作成功分支无法端到端验证」。
> 2026-10-02 i18n 复测中发现**策略页会弹真 polkit 授权框**（见
> `docs/UI-重构进度-阶段-i18n接入.md` §七）→ 该项现**可验证**。
> 完成日期：2026-10-02

---

## 一、待验证的代码契约（三处已通读核实）

| # | 位置 | 契约 |
|---|---|---|
| 1 | `basepage.cpp:62-73` `BasePage::showFeedback(s, text, autoHide)` | `autoHide==true` → `m_feedback->autoDismiss(5000)`；失败/警告传 `false` → **常驻可关** |
| 2 | `components.cpp:546-556` `PanshiInlineBanner::autoDismiss(ms)` | 单发定时器**只在首次创建**，`start()` 重置倒计时（不叠加）；超时动作是 `hide()`（**保留文本**，可复用同一条 Banner） |
| 3 | `components.cpp:522-530` `setText()` | 展示新内容时**先 `m_dismissTimer->stop()`** —— 换内容即换一次反馈，防止旧定时器误杀新 Banner |

**风险点（阶段 4 已修的缺陷，重测时重点看）**：
- 若 `autoDismiss` 每次调用都 `new QTimer` → 定时器叠加，先前的会在新内容刚显示时隐藏它；
- 若 `setText()` 不 `stop()` → 同上；
- 本次核实**两处均正确**（单发 + 重置 / 换内容即停），故预期行为是：
  **Banner 显示 → 计时 → 自行消失，且期间产生新反馈不会被旧计时器误杀。**

## 二、验证入口（按破坏性从低到高）

### 入口 A：创建备份 ⭐ 推荐首选

**位置**：备份与版本 → 备份快照 → 「创建备份」
**代码**：`snapshotspage.cpp:415-420`，成功文案 `备份“%1”创建成功。`，`autoDismiss(3000)`

**为什么选它**：
- 成功分支稳定可达（创建快照不需要关闭保护，是**加法操作**）；
- **不破坏系统**：验证完可在同页点「删除」清理；
- 顺带覆盖 `setText()` 的换内容逻辑（连续创建两次即可验证旧计时器不误杀新 Banner）。

**步骤**：
1. 启动应用 → 侧栏「备份与版本」（默认停在「备份快照」子页）
2. 点「创建备份」→ 输入名称（如 `banner-test`）→ 确认
3. 备份成功后**立刻开始计时**：Banner 应显示「备份"banner-test"创建成功。」
4. **不点任何按钮，观察 3~5 秒** → Banner 应自行消失
5. 表格中应出现该备份（验证副作用）

**对照测试（验证换内容不误杀）**：
- 备份还在列表里 → 立刻**再创建一次**（不同名称）
- 预期：第一次的 Banner 已被隐藏；第二次成功后**新 Banner 完整显示 3 秒**才消失，
  **不应出现「刚显示就被立刻隐藏」**

### 入口 B：删除备份

**位置**：同页，操作列「删除」（初始备份不可删）
**代码**：`snapshotspage.cpp:462-466`，`备份已删除，占用空间已释放。`，`autoDismiss(3000)`

**步骤**：入口 A 完成后 → 点刚建那条的「删除」→ 确认 → 观察 3 秒消失。
**顺带清理测试数据。**

### 入口 C：策略页保存系统参数（验证 5s 档 + pkexec 链）

**位置**：策略与设置 → 「保存系统参数」
**代码**：`policypage.cpp:288-292`，`系统参数已保存`，`autoDismiss(3000)`；
经 `BasePage::showFeedback` 的 5000ms 档由 `masterswitch.cpp:236` 使用

**步骤**：
1. 策略与设置页 → 点「保存系统参数」
2. **本机会弹 polkit 授权框** → **输入密码确认**
3. 成功后观察页内 Banner → 应显示「系统参数已保存」并在计时后消失
4. 失败则会显示 `保存失败: …`（**常驻，不自动消失** —— 这本身就是对照：
   同一 Banner 的成功/失败两态行为必须不同）

> ⚠️ 这一条会**真的改写 `/etc/deepin-immutable-ctl/deepin-immutable-ctl.conf`**
> 的三个键（`auto-rollback-on-failure` / `max-backup-deploys` /
> `auto-refresh-size-threshold`）。建议**先记下原值**再操作，
> 或直接用入口 A 验证（同一机制、3s 档），此入口仅在你愿意改配置时做。

### 不建议：磐石功能开关（成功分支会改系统保护状态）

`masterswitch.cpp:236` 的 `设置成功，请重启系统使设置生效。`（5s 档）需要
关闭/开启只读保护 —— **打开可写层会让核心目录可写**，虽可逆但风险面大。
除非专门要验这一条，否则走入口 A。

## 三、判定标准

| 现象 | 结论 |
|---|---|
| Banner 显示后**在约定时间内自行消失**，期间无操作 | ✅ **通过** |
| Banner 一直常驻，需手动点 × | ❌ `autoDismiss` 未生效（查 `setClosable` 是否误设 true / 定时器未 start） |
| 新 Banner **刚显示就被隐藏** | ❌ 定时器叠加或 `setText()` 未 `stop()`（阶段 4 已修，需回归） |
| 成功后 Banner 常驻、**但失败时常驻也对** | ⚠️ `autoHide` 参数传错（成功/失败两态无法区分） |
| 消失后表格/数据未更新 | 独立问题（`refresh()` 未执行），不属本项 |

## 五、验证后清理

- 删掉测试备份（入口 B）；
- 若做过入口 C，把 `/etc/deepin-immutable-ctl/deepin-immutable-ctl.conf`
  的三个键改回原值；
- 策略页的三个 DSpinBox 若被改动（改的是**应用级** `config.json`，非系统配置），
  如需复位可手动改 `~/.config/panshi-manager/config.json`。

> 注：策略页有两套配置 —— 左半「备份保留策略」是**应用级**（`config.json`，
> 即时保存、无需授权）；右半「磐石系统参数」是**系统级**（写 `/etc/…conf`，需授权）。
> 只有后者会弹 polkit。
