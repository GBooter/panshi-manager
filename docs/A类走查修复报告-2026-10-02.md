## 二、A3-1：本地化盲区（本轮最值得记的一个）

### 现象与影响

| locale | `sudo -n` 失败输出 | 原 `contains("password")` | 结果 |
|---|---|---|---|
| en_US | `sudo: a password is required` | ✅ 命中 | pkexec 回退正常 |
| **zh_CN** | **`sudo: 需要密码`** | ❌ **不含 "password"** | **回退永不触发 → 直接失败 Banner** |

**严重性**：中文是本项目主语言与默认 locale —— 即**主路径失效**，
只有英文实例正常（你的 en_US 实例删除回退正常，正是这个原因）。

> 这是「用英文环境测多语言应用」的经典陷阱：功能在测试环境正常，
> 在**默认语言**下静默失效。

### 修法

抽出独立判定函数（`backend.cpp` 匿名 namespace）：

```cpp
bool needsPassword(const QString &stderrText)
{
    return stderrText.contains(QStringLiteral("password"), Qt::CaseInsensitive)
        || stderrText.contains(QStringLiteral("passphrase"), Qt::CaseInsensitive)
        || stderrText.contains(QString::fromUtf8("密码"));
}
```

**刻意不匹配**「user is not in the sudoers file」——该用户本就无权，
回退只是白等一个授权框。这是**期望行为**，不是缺陷。

> ⚠️ 另一种「修法」是把「读不到密码信息」当作「需要密码」——
> 那会让无权用户在每个 root 操作上都白等一个 polkit 框。**不采用。**

## 三、A3-2：CLI 位置参数不可省略

原实现：

```cpp
if (!name.isEmpty()) args << name;
if (!desc.isEmpty()) args << desc;   // ← 空描述时整个参数消失
```

而 `deepin-immutable-ctl snapshot create` 要求 `<名称> <描述>` **双参数** ——
省略描述导致参数个数不符，**直接失败**。UI 上「描述」标的是「(可选)」，
与 CLI 契约矛盾。

**修法**：按「可选的是**内容**，不是**位置**」处理 —— 位置参数始终传，空串占位：

```cpp
args << (desc.isEmpty() ? QString() : desc);
```

比传 `"无描述"` 这类硬编码文案更干净，且不污染 UI 语言。

**同源缺陷**：`modifySnapshot` 有完全相同的一行，一并修。
（`doRollback` 调 `createSnapshot` 时 desc 非空，故还原流程原本不受影响。）

## 四、A2-1 / A2-2：键盘事件过滤器装错了控件

### 根因（两个现象同源）

搜索态下**焦点始终在 `lineEdit`**：

- `↑↓` 被 `QLineEdit` 消费为**输入历史上下翻**，根本到不了结果列表；
- `Esc` 同理，QLineEdit 有自带行为，我们的状态没被清；
- 而 `m_results` **永远拿不到焦点** —— 点它会走 `clicked` → `activateResult`
  → 立即落地切页（这本身是设计），焦点没机会停留。

原实现把 `eventFilter` 装在 `m_results` 上、且只处理 `Esc`。

> **通用教训**：在「输入框 + 列表」这类组合里，键盘处理必须装在
> **当前持有焦点的控件**上，而不是「逻辑上相关」的那个控件。

### 修法

过滤器同时装两处，并按控件分工：

| 控件 | 处理 | 理由 |
|---|---|---|
| `m_search->lineEdit()` | `Esc` 清空 / `↑↓` 移动高亮（吞掉事件，阻止翻历史） | **焦点实际所在** |
| `m_results` | `Esc` 清空 | 保留：焦点若因程序化 `setFocus` 落到列表上仍能正确退出 |

细节：

- `↑↓` 到末尾/首项**回卷**（`↓` 末→首，`↑` 首→末），符合列表浏览直觉；
- `↑↓` 时 `scrollTo(PositionAtCenter)`，保证选中项在可视区；
- 「无匹配」提示行只有 1 行且 `NoItemFlags`，此时 `↑↓` 直接吞掉不移动；
- `Esc` 在搜索框已空时**不吞事件**，让外层对话框/主窗口的 Esc 语义正常。

## 五、O1-1：号称「单一数据源」，其实只覆盖了一半

### 根因

阶段 3-7b 把单日历改造的立意是「摘要的唯一数据源是 `from`/`to` 状态」，
代码注释也这么写。但实际：

| 视图 | 数据源 |
|---|---|
| **摘要文字** | ✅ `st->from` / `st->to` |
| **日历高亮** | ❌ `QCalendarWidget` **自行维护**（点击时 Qt 内部改 `selectedDate`；切换月份时某些主题/风格也会改） |

**两者是独立状态源**，只是恰好多数时候一致。月份切换即可让它们分叉。

### 修法

让**摘要与高亮都从 `st` 派生** —— `refreshSummary` 里同时回写：

```cpp
cal->setSelectedDate(st->complete ? st->to : st->from);
```

任一路径造成的日历内部漂移，都会在下次 refresh 时被拉回 `st`，
两者在**结构上**不再可能分叉。

**顺带修一个真实 UX 问题**：`complete == false` 时 `from == to`，
原实现仍显示「已选范围：X ~ X」，用户会误以为已选定单日区间而直接确定。
现改为显式提示「已选开始日期：X，请再点击选择结束日期」。

> 无递归风险：`setSelectedDate` 只发 `selectionChanged`，
> `clicked` 仅由用户点击触发。

## 六、O2-1 / O6-1：两个「API 都调用了，但结果不对」

### O2-1：容量条文字不渲染

`setTextVisible(true)` 与 `setFormat()` **都正确调用了**，但文字不显示。
根因是 `setFixedHeight(14)` —— QProgressBar 的文字画在**槽内**，
14px 放不下文字行高，被裁掉了。

修法：新增 token `Size::ProgressWithText = 18`（能显示文字的最小档）。
用 token 表达「带内嵌文字的进度条」这一语义；纯 L3 顶部细条仍用 `ThinProgress(2)`。

### O6-1：步进 1.0 ≠ 预期 0.1

`setDecimals(1)` 只影响**显示**（3.0）。`QDoubleSpinBox` 的默认
`singleStep` 是 **1.0**，**不随 decimals 变化** → 键盘 `↑↓` 一次跳 1.0。

修法：显式 `setStep(0.1)`。

> **通用教训**：`setDecimals` 与 `setStep` / `setSingleStep` 是**两件事**。
> 看到「显示一位小数」不等于「能一位一位调」。

## 七、A2-3：把「读不到」变成可诊断

`reduceMotionRequested()` 读 `org.deepin.dde.appearance` 的 `enable-animations`。
若该发行版 schema **无此键**，`value(key, true)` 静默返回默认 true →
`reduce` 恒 false，「减少动态效果」开关对本应用无效，且**无任何日志**。

修法：用 `keyList()` 显式判存在性，缺键时打 `qWarning`（用 `qWarning` 而非
`qInfo`，因本项目 `QT_LOGGING_RULES` 屏蔽了后者）。

**刻意不采用**「读不到就当作要减少动效」—— 那会让所有动效在缺键系统上
被整体关掉。**静默降级比不降级更糟。**

> ⚠️ **API 名是 `keyList()`，不是 `keys()`** —— 我第一版写成了 `keys()`，
> 查 DTK 文档后改回。写错会直接编译失败。
> 这也是「先查官方文档再定方案」的一次实证。

### 11.2 V-16：我的根因判断是错的，且已换方案

**我原先的判断**：「14px 装不下文字行高，被裁掉」→ 提到 18px。
**实测结论**：**DTK6 的 `DProgressBar` 样式根本不绘制内嵌 `format` 文字**
—— 像素级检查条内无任何文字像素，18px 同样无效。

即 `setTextVisible(true)` 在**继承链上有效**，但样式层未实现
`CE_ProgressBarLabel`（DTK 文档 `style-impl.md` 列了该绘制入口，
**但「文档写了」≠「实现存在」**）。

> **教训**：控件「某个 `setXxx` 调了但没效果」时，
> **先查样式层是否实现该绘制入口**，不要先怀疑尺寸/裁剪。
> 我从「Qt 原生 `QProgressBar` 会画文字」类推出「继承来的也该会」，
> 跳过了样式层这一环。

**新方案：百分比外置**

| | 之前 | 现在 |
|---|---|---|
| 条 | `DProgressBar` + `setFormat` + `setTextVisible(true)` + 18px | `DProgressBar` 纯形状，14px（`Size::UsageBarHeight`） |
| 百分比 | 依赖条内绘制 | **独立 `DLabel`**（`m_usagePct`，`Size::UsagePctWidth` 固定宽、右对齐、T4） |
| 语义色 | 仅大数值 | **大数值 + 百分比同步染色**（同一 `usageRole`） |
| 无盘符分支 | `setFormat("--")` | `m_usagePct` 回落 `--` 且色归 `TextTips` |

顺带改进两处：
- **两个标签同步染色** —— 否则「大数值变红、百分比还是黑的」自相矛盾；
  WCAG 1.4.1 仍成立（数值本身写着，不依赖颜色）。
- **无盘符时百分比标签一并回落** —— 否则会残留上次的语义色。
- 标签**固定宽度 56px** —— 1 位/2 位小数宽度不同，固定宽避免条被推着左右移动。

> 附带收益：不再依赖控件内部绘制实现，DTK 升级也不受影响。

### 12.3 B3 揪出的两个打包缺陷（用户代修，已核实）

**① `.qm` 根本没生成 install 规则**

| 事实 | 后果 |
|---|---|
| `qt_add_translations(... RESOURCE_PREFIX "/i18n")` 只把 `.qm` 编进 **Qt 内嵌资源** | 体积翻倍，但没人读它 |
| **`DApplication::loadTranslator()` 只搜文件系统、不读 Qt 资源** | 内嵌译文**永远不会被加载** |
| 该宏**不生成 install 规则** | 干净系统上安装版**没有任何 `.qm`** |

→ 英文界面在干净机器上**静默回落中文，无任何报错**。
**此前所有 i18n 测试能通过，全靠手工 `cp` 到 `~/.local` 掩盖了它。**

修法：`QM_FILES_OUTPUT_VARIABLE` 取出 + `install(FILES …)` 显式安装到
`share/panshi-manager/translations/`。**Qt6.8 里它与 `RESOURCE_PREFIX` 互斥。**

**② `.desktop` 的 `Exec` 写死绝对路径** → 装 `/usr/local` 后开始菜单失效。
修法：`configure_file` + `@PANSHI_BINDIR@` 占位符（`install.sh` 用 `sed` 替换）。

**终验**：无 `LD_LIBRARY_PATH`、无任何模拟变量，直接跑
`/usr/local/bin/panshi-manager`（系统自带 DTK 6.7.47）——
zh_CN 全中文且无 qm 缺失告警、en_US 标题栏 + 备份页全英文、磁盘页真实数据正常。

**良性遗留**：启动有 `Can't acquire config manager` 告警 ——
DSG 库硬编码只认只读 `/usr/share/dsg`，`DSG_DATA_DIRS` 在这版 DTK **实测不生效**。
磁盘监控配置有 `QSettings` 兜底（GUI 实测正常读写），非本次回归；
打包镜像（`/usr` 可写）时自然消失。

### 12.4 C7：我的方案被实测否决

我提议的 `SUDO_ASKPASS` 指向 sleep 脚本 **无效**：
应用走 `sudo -n`（**0.047s 即失败**），`-n` 是非交互模式、**不调用 askpass**；
`LD_PRELOAD` 注入被宿主沙箱 `sbox.so` 清洗。

**用户改用纯用户态 SIGSTOP watcher（正解）**：
- 冻**慢的**那个（`ctl` 太快抓不住，冻结的是 **~90ms 的 `ostree`**）
- 轮询 50ms 级、`pgrep -n -f` 取最新进程（命令会连续起多个）
- 帧证据：**+4.24s 仍加载、+4.74s 对话框出现**（4s 定时器 + 弹框动画），
  对照正常路径 **~1.8s** → 两路径明显分离；拆除后刷新完整恢复

→ 方法论已沉淀为工作区技能
`.workbuddy/skills/backend-fault-injection/SKILL.md`（含手段有效性对比表）。

### 12.8 脚本代修：我的「探测安装前缀」是段静默失效的代码

**用户代修并指出**：我写 `sed 's|^CMAKE_INSTALL_PREFIX:PATH=||p'`
读 `install_manifest.txt` 推断前缀 —— 但 **manifest 是文件路径清单、
不含该变量**（变量在 `CMakeCache.txt`）→ sed **永远落空**，
而 fallback `/usr/local` 在本机**恰好正确** → **静默掩盖了一个真 bug**：
装 `/usr` 的形态会检测错前缀。

**正确做法**（已代修）：从 manifest **首行** `/usr/local/bin/panshi-manager`
剥掉 `/bin/panshi-manager` 后缀反推 —— 取自**产物本身**，
不依赖构建期变量（构建目录可能已清理）。

我已在脚本里补上**显式告警**：探测失败时走 stderr 提示
「未能推断前缀，回落 /usr/local —— 若实际装到别处，下面检查路径会全错」。

> **通用规则**：**「探测失败」与「探测到别的值」必须能区分**。
> 二者走同一条静默默认路径时，恰好正确的环境会掩盖解析逻辑的错误。

### 12.9 用户追加的一条同类教训：状态守卫的覆盖范围要先核实

用户原计划「冻结 `refresh` 进程以触发『上一项操作尚未完成』Warning banner」，
**扑空** —— 因为 `SnapshotsPage::m_running` 只在
`onCreate` / `onDelete` / `doRollback` 等**写操作**入口检查，
**`refresh()` 完全不碰它**。

> **通用规则**：造故障前确认「守卫/判据在这条路径上真的会被求值」。
> 且注意同一语义可能有多套独立状态（本项目 `m_inFlight` 管后台任务、
> `m_running` 管写操作），**不可互相假设**。

两条教训（12.8 / 12.9）已写入 `MEMORY.md` §四.10 / §四.11
与技能 `backend-fault-injection` §6.1 / §6.2。
